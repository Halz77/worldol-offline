# 开发指南（小白向）

> 这份文档写给**第一次接触 Godot、想自己动手改这个项目**的人。
> 目标不是讲完 Godot 的所有知识，而是让你能在 30 分钟内：把工程跑起来 → 看懂界面 → 找到要改的文件 → 改 → 验证没改坏。
>
> 工程里还有四份文档，分工不同，别混着看：
>
> | 文档 | 给谁看 | 什么时候看 |
> |---|---|---|
> | **开发指南.md**（本文） | 人，尤其新手 | 第一次上手、忘了操作步骤 |
> | `AGENTS.md` | 接手写代码的人/AI | 动渲染、装备、外观这类核心逻辑前查规则 |

>
> 阅读建议：只想玩 → 第 1、2 章；想改东西 → 第 1、2、3、6 章；想系统学 Godot → 按顺序读，第 12 章有一串练手任务。

## 1. 装好工具，把工程打开

### 1.1 下载 Godot（只下标准版）

到 <https://godotengine.org/download> 下载 **Godot 4.7.x 标准版（Standard）**，不要下 .NET / Mono 版。

为什么强调这个：本工程的 `project.godot` 里写的是 `features=PackedStringArray("4.7", "GL Compatibility")`，没有 dotnet 配置段。用 Mono 版打开会把工程标记改写成带 C# 的版本，之后标准版再打开就会提示不匹配。

本机已经装好了，路径是：

```
E:\Godot_v4.7.2-stable_win64\Godot_v4.7.2-stable_win64_console.exe
```

同一目录下还有一个 `Godot_v4.7.2-stable_win64.exe`。两个都能用，区别只有一个：

- **带 `_console` 的那个会在终端打印日志**（`print()` 的输出、报错堆栈）。
- 不带 `_console` 的版本，日志只写进编辑器底部的「输出」面板，命令行里看不到。

结论：**写代码、排查问题时用 `_console` 版**；双击图标当普通软件用就随便。

### 1.2 导入工程

1. 打开 Godot，出现「项目管理器」窗口。
2. 点右上角 **「导入 / Import」**。
3. 点「浏览 / Browse」，选到工程里的 **`project.godot`** 文件：
   ```
   C:\Users\hal\WorkBuddy\2026-10-24-23-22-43\godot-next\project.godot
   ```
4. 弹窗里「项目路径」保持默认，点 **「导入并编辑 / Import & Edit」**。
5. 第一次导入会花一两分钟扫描素材（约 1.2 万个文件），底部有进度条，**不要以为卡死了**。

如果这个工程之前已经在列表里，直接双击列表项即可。

> F 盘还存着一份仓库副本（`F:\...\世界OL_源码\godot-next`）。两份是同一个工程，改哪份都行，但**不要同时开两个编辑器改同一批文件**。日常在 C 盘工作副本里改，原因见第 11 章。

打开后看到的是这个布局，我用「你要用它干什么」来解释：

| 编号 | 面板 | 你会在什么时候用它 |

### 1.4 三个必须记住的快捷键

| 键 | 作用 | 在本工程里意味着什么 |
|---|---|---|

| **F6** | 只运行**当前打开的场景** | 你正开着 `WorldScreen.tscn` 时按 F6，直接进地图屏，跳过角色屏 |

还有一个新手最容易踩的：**改完代码要先保存（Ctrl+S），再按 F5**。没保存的文件标签上有个小圆点，运行时跑的还是旧代码。

### 2.3 存档在哪

这个项目把所有玩家状态都写在 Godot 的 `user://` 目录，Windows 上对应：

```
C:\Users\<你的用户名>\AppData\Roaming\Godot\app_userdata\世界OL 单机重做\
```

里面三个文件，各管一摊，互不影响：

| 文件 | 内容 |
|---|---|
| `character_screen.json` | 性别、姿势、动作、缩放、背景、上次看的地图 |
| `equipment.json` | 身上穿的 14 个部位 |
| `appearance.json` | 发型 / 脸型 / 手 / 脚 + 四个自由调色颜色 |

**删掉某个文件 = 那一项恢复默认**，不会连带清空别的。这是排查"界面状态不对"最快的办法，比读代码快。

> 注意：三个文件都带 `version` 字段。以后想加字段，要么给默认值，要么升版本号并写迁移；**不要直接把 version 改大**，那会让老存档整体失效。

- 想看数据结构：随便翻。
- 想改内容：**不要直接改这里**。改 `data/overrides/`（覆盖层），或先用对应的编辑器改，原因见 6.3。

## 4. 五个 Godot 概念，用这个工程当例子

不背概念，直接对着代码看。

### 4.1 场景（Scene）= 一棵节点树（Node Tree）

打开 `scenes/WorldScreen.tscn`，左侧「场景」面板显示：

```
WorldScreen            ← 根节点，挂 WorldScreen.gd
├─ WorldMap            ← 地图，挂 WorldMap.gd
│  ├─ Layers           ← 图层容器（子节点运行时按地图生成）
│  ├─ Npcs             ← NPC 容器
│  └─ Names            ← 名字标签容器
├─ Player              ← 小人
│  └─ Sprite           ← AnimatedSprite2D，显示当前帧
├─ Camera2D            ← 跟随小人的相机
└─ UI                  ← 所有界面控件（CanvasLayer 里）
```

**要点**：

- 节点靠**父子关系**组织，父节点移动，子节点跟着动。
- 兄弟节点里，**后面的画在上面**（同层级靠顺序决定绘制顺序）。
- 场景可以嵌套：`WorldScreen` 里的 `Player` 本身也可以是一个独立场景，只是这里为了简单直接写在里面了。

### 4.2 脚本（Script）= 挂在节点上的行为

一个 `.gd` 文件通过 `extends` 声明它"是什么类型"，然后被挂到某个节点上：

```gdscript
extends Node2D                     # 我是一种 2D 节点
## 世界地图屏：地图选择器 + 可行走角色 + NPC 信息。

@onready var world_map: Node2D = $WorldMap    # $ 就是"取子节点"
```

三个最常见的写法：

| 写法 | 意思 |
|---|---|
| `@onready var x = $Path` | 场景加载完再取子节点（`_ready` 之前节点还没进来） |
| `func _ready()` | 节点进入场景树时执行一次，用来初始化 |
| `func _process(delta)` / `_physics_process(delta)` | 每帧/每物理帧执行，`delta` 是距上一帧的秒数 |

**看这个工程的例子**：`WorldPlayer.gd` 的 `_physics_process` 里读 WASD、算位移、碰墙就不走——这就是"每帧做一次"的典型用法。

### 4.3 Autoload = 全局单例

`project.godot` 里有这一段：

```ini
[autoload]
ScreenState="*res://scripts/ScreenState.gd"
```

意思是：游戏启动时先实例化 `ScreenState.gd`，挂在 `/root/ScreenState` 上，**任何场景都能随时访问**。

为什么需要它：角色屏、装备屏、外观屏、地图屏都要读同一份"玩家状态"（性别、装备、外观、上次看的地图）。如果每个场景各存一份，切场景就丢了。

代码里两种拿法：

```gdscript
var state = get_node_or_null("/root/ScreenState")   # 正经写法
```

本工程还额外写了兜底：拿不到就自己 new 一个（`CharacterScreen.gd` 的 `_ready` 里有），这样验收脚本脱离完整工程也能跑。

**它怎么通知别的界面"状态变了"**——靠信号：

```gdscript
state.state_changed.emit("look")     # 发射
...
state.state_changed.connect(_refresh)  # 订阅
```

角色屏、装备屏、地图小人全都订阅了同一个信号，所以你在外观屏改一个发色，回车/返回后三处颜色一致。

> 记住这条**设计原则**：状态集中在 `ScreenState`，界面只负责"显示"和"把用户操作翻译成 setter 调用"。不要在界面脚本里另存一份装备数据，那是 bug 的源头。

### 4.4 资源（Resource）= 存在磁盘上的数据块

`.tscn`（场景）、`.tres`（自定义资源）、`.png`（纹理）都是资源。本工程最重要的一个资源是：

```
assets/tilesets/map_ground.tres
```

它是 Godot 的 **TileSet** 资源：206 张切片图 → 206 个「来源」，每个来源被切成 24×24 的小格 → 920 个图块，外加 1164 个镜像变体。第 5 章会教你怎么打开看。

### 4.5 信号（Signal）= 一对多的"广播"

引擎自带很多信号（按钮 `pressed`、列表 `item_selected`），你也可以自己定义。本工程大量使用：

```gdscript
# WorldScreen.gd
npc_check.toggled.connect(func(v): world_map.call("set_show_npcs", v))
```

这行的意思是：勾选框状态一变，就调用地图的 `set_show_npcs(v)`。**用信号代替"到处轮询"**，是 Godot 里最省心的写法。

## 5. 怎么看图层（重点，一步步照做）

先解释一个容易懵的点：

> **地图的图层是运行时按地图数据建的，编辑器里打开 `WorldScreen.tscn` 看不到它们。**
> 这不是 bug。`WorldMap.gd` 在 `load_map()` 里读地图 JSON，然后 new 出 7~9 个节点挂到 `Layers` 下面。

所以查看分两条路：**运行起来看**（推荐）和**不开界面看**（终端打印）。

### 5.1 第 1 步：打开工程

Godot 项目管理器 → 双击工程（或「导入」选 `project.godot`）。见 1.2。

### 5.2 第 2 步：打开场景

左下「文件系统」面板里展开 `scenes` 文件夹，**双击 `WorldScreen.tscn`**。

这时「场景」面板（左上）显示：

```
WorldScreen
├─ WorldMap        ← 地图脚本在这里
│  ├─ Layers       ← 空容器，图层运行时才长出来
│  ├─ Npcs
│  └─ Names
├─ Player
│  └─ Sprite       ← 现在是 AnimatedSprite2D（不是普通 Sprite2D）
├─ Camera2D
└─ UI
```

`Layers` 是空的，不要慌，下一步就看到了。

### 5.3 第 3 步：按 F6 运行，切到 Remote

1. 按 **F6**（运行当前场景，直接从地图屏开始）。
2. 游戏窗口出来后，**回到编辑器**，看左上「场景」面板的左上角，有两个小标签：**「本地 / Local」**和**「远程 / Remote」**。
3. 点 **「远程 / Remote」**。
4. 展开 `WorldScreen → WorldMap → Layers`，你会看到：

```
Layers
├─ Layer5_tiles      ← 地块层（TileMapLayer），地面砖块
├─ Layer5_tone       ← 压暗层（只有 100 号地图有），半透明黑
├─ Layer4_objects    ← 物件层（MapObjectLayer），桌椅树木
├─ Layer3_tiles
├─ Layer2_objects
├─ Layer1_objects
└─ Layer0_objects
```

**注意顺序**：列表里 `Layer5` 在最上面，`Layer0` 在最下面——但**绘制恰恰相反**：`layers[0]` 是画在最上层的。这一点第 5.7 节解释。

### 5.4 第 4 步：试三个动作，理解"图层是节点"的好处

**动作 A：单独看一层**
点中 `Layer3_tiles`，右侧「检查器」里找到 **`Visible`**（可见），把勾去掉 → 那一层立刻消失。挨个关一遍，你就知道每层画的是什么了。

想快速排查"这块地形为什么不对"，就只留可疑的那层。

**动作 B：看图块数据**
点中任意 `Layer*_tiles`，检查器里有：

| 属性 | 含义 |
|---|---|
| `Tile Set` | 指向 `assets/tilesets/map_ground.tres`，所有地块层**共用同一个** |
| `Tile Map Data` | 这一层实际铺了哪些格子（运行时生成的数据） |
| `Texture Filter` | 保持 `Parent Node`，**不要改成 Nearest**（会差 3.6% 像素，见第 10 章） |

**动作 C：看小人的动画**
展开 `Player → Sprite`，检查器里能看到：

| 属性 | 值 |
|---|---|
| `Sprite Frames` | 里面有 `idle`、`walk`、`action0`… 几条动画 |
| `Animation` | 当前在播哪条（走路时是 `walk`） |
| `Frame` / `Speed Scale` | 第几帧 / 速度倍率 |

点开 `Sprite Frames` 下面的动画列表，还能直接看每条动画的帧率（`idle` 4fps、`walk` 7fps）。

### 5.5 第 5 步（不想开界面时）：终端打印节点树

在 `godot-next` 目录下跑：

```bat
set WORLDOL_TREE=1
set WORLDOL_MAP=100
"E:\Godot_v4.7.2-stable_win64\Godot_v4.7.2-stable_win64_console.exe" ^
  --path . res://scenes/WorldScreen.tscn
```

控制台会打印整棵树，包含每个图层节点名、类型、铺了多少格。**排查"某层没建出来"时比翻界面快。**

实测输出长这样（地图 100 号）：

```
┖╴WorldMap
   ┠╴Layers
   ┃  ┠╴Layer5_tiles
   ┃  ┠╴Layer5_tone
   ┃  ┠╴Layer4_objects
   ┃  ┠╴Layer3_tiles
   ┃  ┠╴Layer2_objects
   ┃  ┠╴Layer1_objects
   ┃  ┖╴Layer0_objects
   ┠╴Npcs
   ┖╴Names
```

窗口会一直开着，看完直接关掉。想让它自动退出就在前面再加两个变量：
`set WORLDOL_CAPTURE=1` 和 `set WORLDOL_QUITAFTER=2`（会顺带存一张截图，见 8.4）。

改 `WORLDOL_MAP` 的值可以换地图；不设就默认 4 号。

### 5.6 第 6 步：看图块库本身

双击 `assets/tilesets/map_ground.tres`，底部会打开 **TileSet 编辑器**：

- 左边「来源 / Sources」列表：每个来源 = 一张 `map_slice` 图的名字。
- 右边网格：每格是 24×24 的图块，鼠标悬停能看到坐标（`(col, row)`）。
- 带小箭头的格子是**镜像变体**（同一张图左右/上下翻转），地图里用到翻转时才会建。

这就是"图层为什么能一层层关掉"的物质基础：**图块是编号的，图层只是编号的排布**。

### 5.7 为什么图层要倒序建

原版游戏（Egret 引擎）的做法是 `for i = layers.length-1 downto 0: addChild(layer[i])`，**先加的在下面**，所以 `layers[0]` 最后加、显示在最上层。

Godot 这边保持一致：建节点时也倒着建。如果改成正序，`layers[0]` 会跑到最底下，画面会糊成一片色块。

> 这条写在 `AGENTS.md` 里了。你改渲染顺序前先读它，能省半天。

## 6. 三条日常开发路线

新手最容易迷路的地方：**"我要改的东西到底在哪个文件？"** 按目的分三条路。

### 6.1 路线 A：改界面（不动逻辑）

**改什么**：文字、颜色、位置、按钮大小、面板层级。

**怎么改**：

1. 双击 `scenes/XxxScreen.tscn`。
2. 在「场景」面板点中要改的节点。
3. 右侧「检查器」改属性（`Text`、`Font Size`、`Color`、`Size`…）。
4. `Ctrl+S` 保存，F5/F6 看效果。

**什么时候必须重跑生成器**：

| 场景 | 生成器 | 说明 |
|---|---|---|
| `CharacterScreen.tscn` | `tools/build_scene.gd` | **会覆盖手改** |
| `EquipScreen.tscn` | `tools/build_equip_scene.gd` | **会覆盖手改** |
| `WorldScreen.tscn` | `tools/build_world_scene.gd` | **会覆盖手改** |
| `AppearanceScreen.tscn` | 无（手写） | 直接改就行 |

规则很简单：**只有"要新增/删除一批控件、调整整体结构"时才重跑生成器**；调颜色改文字这类，永远直接改 `.tscn`。重跑前先 `git diff` 确认没有没保存的手改，或者干脆先提交一次。

### 6.2 路线 B：改素材（换图）

**情况 1：换角色部件 / 物件 / UI 图**

直接把新的 PNG 覆盖到 `assets/` 对应目录，文件名保持一致。回到游戏：

- 角色屏按 **`R`**（重新载入素材）→ 立刻生效。
- 或者关掉重开。

原理：`SpriteComposer` 直读原始 PNG 并按文件修改时间缓存，没有"导入"这一步。

**情况 2：换地块切片图（`map_slice/*.png`）**

多一步，因为地块走的是烘焙好的图块库：

```bat
rem 1) 换图（文件名不变）
rem 2) 重跑图块生成器
"E:\Godot_v4.7.2-stable_win64\Godot_v4.7.2-stable_win64_console.exe" ^
  --headless --path . --script res://tools/build_map_tileset.gd

rem 3) 跑资产闸门确认没漏
"E:\Godot_v4.7.2-stable_win64\Godot_v4.7.2-stable_win64_console.exe" ^
  --headless --path . --script res://tools/verify_assets.gd
```

**忘了第 2 步会怎样**：地图上那块还是旧图，甚至空白。闸门会直接告诉你"图块库过期：['304']"。

**情况 3：加一张新地图、或让地图用上新的翻转**

也要重跑 `build_map_tileset.gd`——它会重新扫一遍所有地图，把新用到的「资源 + 翻转组合」补成变体。

### 6.3 路线 C：改数据（NPC、道具、地图）

先分清两个目录：

| 目录 | 性质 | 能改吗 |
|---|---|---|
| `data/compiled/` | 从原版编译出的**只读快照** | 不改。改了下次重编译会被覆盖，而且没有版本记录 |
| `data/overrides/` | 手工**覆盖层**，优先于 compiled | 改这里，或者用编辑器改 |

当前有三类覆盖：

| 文件/目录 | 覆盖什么 | 怎么改 |
|---|---|---|
| `data/overrides/maps.json` | 地图的元数据（名字、是否有视觉配置） | 地图编辑器里"改名"会写这里 |
| `data/overrides/map_names.json` | 地图显示名 | 同上 |
| `data/overrides/npcs/` | NPC 展厅的分页数据 | 用 NPC 编辑器改，别手写 |

**用编辑器改（推荐）**：

```bat
rem 地图编辑器
"E:\Godot_v4.7.2-stable_win64\Godot_v4.7.2-stable_win64_console.exe" ^
  --path . res://tools/map_editor/MapEditor.tscn

rem NPC 编辑器
"E:\Godot_v4.7.2-stable_win64\Godot_v4.7.2-stable_win64_console.exe" ^
  --path . res://tools/npc_editor/NPCEditor.tscn
```

地图编辑器的核心操作（详见 `docs/地图编辑与重命名指南.md`）：

| 输入 | 动作 |
|---|---|
| `T` | 地块画笔（画地面） |
| `B` | 阻挡画笔（画"不能走"的格子） |
| `O` | 物件画笔（摆桌椅树木） |
| 左键拖动 | 用当前画笔连续画 |
| 右键拖动 | 擦除 |
| `Ctrl+Z` | 撤销 |
| `Ctrl+S` | 保存（直接写 `assets/map/<id>.json`，**回游戏 F5 立刻生效**） |

### 6.4 加一个新界面（完整清单）

以"做一个背包界面"为例，照这个顺序做，一步都不省：

1. **建场景**：`scenes/BagScreen.tscn`，根节点用 `Control`。
2. **建脚本**：`scripts/BagScreen.gd`，第一行 `extends Control`，然后在场景根节点上挂好。
3. **接数据**：需要玩家状态就 `var state = get_node_or_null("/root/ScreenState")`；需要道具数据就 `GameData.new()`。
4. **加入口**：在 `CharacterScreen.tscn` 顶部加个按钮，信号连到 `_on_bag()`，里面 `get_tree().change_scene_to_file("res://scenes/BagScreen.tscn")`。
5. **写返回**：`Esc` 或返回按钮 `change_scene_to_file("res://scenes/CharacterScreen.tscn")`。
6. **加验收**：复制一份 `tools/verify_equipment.gd` 改名，把断言改成你要保证的行为（第 9 章）。
7. **加进自检**：在 `自检.cmd` 的 for 循环里加 `verify_bag`。

## 7. 读代码的顺序（别从 1270 行的 WorldMap 开始）

新手最容易犯的错：打开最大的文件，看两屏就放弃。按"数据流向"读，从简单的开始。

### 7.1 推荐顺序（每条只说一句）

```
① CharacterScreen.gd   → 一个界面怎么被搭起来、按键怎么接
② CharacterPlayer.gd   → 怎么调 SpriteComposer 画一个人
③ SpriteComposer.gd    → 一个人是怎么被"拼"出来的（读缓存与拼图部分即可）
④ ScreenState.gd       → 状态怎么存、怎么广播
⑤ WorldScreen.gd       → 换地图屏，逻辑几乎一样，能看懂 90%
⑥ WorldPlayer.gd       → 移动、碰撞、走路动画
⑦ WorldMap.gd          → 最后看，只看 load_map / 建图层的部分，其余当工具库
```

装备和外观属于"规则层"，等你把上面七步走完再看：

```
Equipment.gd    → 部位表、属性加成、外观决策
Appearance.gd   → 图号公式、可选档位、调色表
Recolor.gd      → 像素级调色算法（纯函数，可以单独读）
```

### 7.2 一条完整调用链（按 E 之后发生了什么）

这条链能串起大半个工程，建议对着代码走一遍：

```
按 E
 └ CharacterScreen._on_equip()                  切场景到 EquipScreen.tscn
    └ EquipScreen._ready()                      建四个列表
       └ _refresh_candidates()                  列出候选装备（带图标）
          └ ItemIcons.texture(bagIcon)          编号 → 图集里的一块矩形
             └ AtlasTexture                     传给 Button.icon

点一件装备
 └ EquipScreen._on_item_selected()              写进 state
    └ ScreenState.equip(slot, id)               存盘 + 广播 state_changed("equip")
       └ CharacterPlayer.refresh()              订阅者重新画
          └ Equipment.appearance(...)           算出：换哪些部件 + 用哪个 model
             └ Appearance.apply(...)            再叠加发型/肤色/调色
                └ SpriteComposer.render_frame_equipped(...)   拼图
                   └ Image → ImageTexture       贴到屏幕上
```

**建议做法**：在 `ScreenState.equip` 第一行打个断点（行号左边点一下），然后按 E、点装备，一步步 F10 单步走完这条链。走一次，比读十遍代码有效。

## 8. 调试四件套

### 8.1 print 大法（最常用）

```gdscript
print("[bag] 载入道具 ", items.size(), " 件")
```

- 用 `_console.exe` 启动 → 输出在终端。
- 用普通版或编辑器运行 → 输出在底部「输出」面板。
- 看输出前先按 F8 停下，否则界面切走就找不到了。

小技巧：统一用 `[模块名]` 前缀，日志多的时候一眼能筛。

### 8.2 断点

编辑器里点代码**行号左边的空白**，出现红点就是断点。运行到那儿会暂停，底部「调试器」面板能看到：

- **调用栈**：谁调用了这个函数（配合 7.2 那条链特别好用）。
- **局部变量**：当前所有变量的值。
- **单步**：`F10` 下一步（不进入函数）、`F11` 进入函数、`F12` 跳出。

### 8.3 Remote 场景树（运行时看真实结构）

见 5.3。除了看图层，还能：

- 运行时改属性（改完立刻看到效果，用来试探"这个值改成多少合适"）。
- 运行时看到所有动态 new 出来的节点（图层、NPC 精灵、名字标签）。

### 8.4 截图法（改渲染时的保命手段）

这个项目有近 300 张地图，靠眼睛看不完。所以做了一套"截图 + 逐像素比对"的流程。

**基本用法**（必须是正常窗口，headless 截不了）：

```bat
set WORLDOL_CAPTURE=1
set WORLDOL_MAP=100
set WORLDOL_QUITAFTER=2
"E:\Godot_v4.7.2-stable_win64\Godot_v4.7.2-stable_win64_console.exe" ^
  --path . res://scenes/WorldScreen.tscn
```

产物：`_out/world_screen.png`。

**各屏的产物与开关**：

| 场景 | 产物 | 可用开关 |
|---|---|---|
| `WorldScreen.tscn` | `_out/world_screen.png` | `WORLDOL_MAP`（地图 id）、`WORLDOL_FIT=1`（整图适配）、`WORLDOL_ONLYLAYER=5`（只显示某层） |
| `CharacterScreen.tscn` | `_out/character_screen.png` | `WORLDOL_LOOK`、`WORLDOL_SEX`、`WORLDOL_POSE` |
| `AppearanceScreen.tscn` | `_out/appearance_screen.png` | `WORLDOL_LOOK` |
| `EquipScreen.tscn` | `_out/equip_screen.png` | `WORLDOL_EQUIP`（例 `weapon:20300,clothes:10032`） |

**`WORLDOL_LOOK` 的写法**（只改内存、不写盘，不会污染存档）：

```
set WORLDOL_LOOK=hair_style:5,hair_rgb:#ff8800,face_rgb:#9fd6a8
```

**怎么比对新旧两张图**：

1. 改代码**之前**，用同一分辨率截一张，另存为基准。
2. 改完再截一张。
3. 用图像工具（或自己写十几行 GDScript）统计差异像素数。

本项目就是靠这个方法发现两个真 bug 的：一个纹理过滤差异（3.6% 像素）、一个补缺图传染（121 格颜色全错）。**肉眼完全看不出来**。

关键点：**分辨率必须一致**，否则缩放会让每个像素都不同。用 `--resolution 1200x960` 固定窗口大小。

## 9. 自检：为什么这个工程能一直改不坏

### 9.1 一键跑全部检查

双击工程根目录的 **`自检.cmd`**，或在命令行：

```bat
cd /d C:\Users\hal\WorkBuddy\2026-10-24-23-22-43\godot-next
自检.cmd
```

Godot 装在别处就先设一下：

```bat
set GODOT=D:\Godot\Godot_v4.7.2-stable_win64_console.exe
自检.cmd
```

它会按顺序跑 8 项，最后输出 `[OK] all checks passed` 或 `[FAILED] some checks failed`。**失败时退出码非 0**，能直接接进自动化。

### 9.2 八项各管什么

| 脚本 | 管什么 |
|---|---|
| `verify_assets.gd` | **资产闸门**：地图引用的图块/物件、角色部件、道具图标、NPC 造型、UI 图集是否都存在 |
| `verify_world_map.gd` | 地图渲染：图层节点、图块、变换、补洞、NPC、小人与动画 |
| `verify_map_editor.gd` | 地图编辑器：读写、撤销、校验、新建/复制 |
| `verify_npc_showcase.gd` | NPC 展厅：去重口径、分页、字段完整性 |
| `verify_character_screen.gd` | 角色屏：性别/姿势/动作/帧、存档往返 |
| `verify_equipment.gd` | 装备：部位判定、属性加成、外观换算、界面图标 |
| `verify_appearance.gd` | 外观：图号公式、档位、替换键、调色算法、存档 |
| `verify-data-compile.gd` | 数据编译：分片数量、字段、引用完整性 |

> **必须串行跑**。好几套验收共用 `user://` 存档，同时跑会互相踩，出现"单独跑能过、一起跑就红"的假失败。

### 9.3 验收脚本长什么样

打开任意一个 `verify_*.gd`，结构都一样：

```gdscript
extends SceneTree

var failures := 0

## ok 为 false 时计数 +1，最后靠失败数决定退出码。
func ck(label: String, ok: bool, detail: String = "") -> void:
    if ok:
        print("[check] ok - ", label, (" · " + detail) if detail != "" else "")
    else:
        failures += 1
        printerr("[check] FAIL - ", label, " ", detail)

func _initialize() -> void:
    # 1) 准备数据
    # 2) 一条条断言
    ck("默认女 · 正常 → Model 300", int(state.call("model_id")) == 300)
    # 3) 汇总
    print("[verify] 失败项 ", failures)
    quit(1 if failures > 0 else 0)
```

两个必须知道的写法：

- `_initialize()` 而不是 `_ready()`：`--script` 模式下场景树还没进入帧循环，写在 `_ready` 里不会执行。
- 要测场景就把场景 `instantiate()` 后 `get_root().add_child()`，再取子节点断言。

### 9.4 自己加一条检查

假设你加了个"背包能装 20 件"的功能，想保证它不退化：

1. 复制 `tools/verify_equipment.gd` 为 `tools/verify_bag.gd`。
2. 把里面无关的断言删掉，留下框架（`ck`、`failures`、末尾的 `quit`）。
3. 加你的断言：
   ```gdscript
   var bag = load("res://scripts/Bag.gd").new()
   for i in range(25):
       bag.add(1000 + i)
   ck("背包上限 20 件", bag.count() == 20, str(bag.count()))
   ```
4. 命令行单跑：
   ```bat
   "E:\...\Godot_v4.7.2-stable_win64_console.exe" --headless --path . ^
     --script res://tools/verify_bag.gd
   ```
5. 加进 `自检.cmd` 的 for 列表。

**验收的判断标准**：不是"能跑通"，而是"你故意把它改坏，它会红"。改坏一次试试，红不了说明这条断言是摆设。

### 9.5 资产闸门在防什么

这个工程最贵的一类 bug 是**静默失败**：图不存在 → 那一格不画 → 不报错 → 只有人眼能发现。

`verify_assets.gd` 把这件事变成"构建期失败"：

- 已知缺口（原版客户端本身就没下发的文件）登记在 `data/asset_allowlist.json`，只提醒不拦。
- **基线之外出现任何新缺口 → 退出码 1**，并打印"哪个名字 ← 哪张地图（几处）"。
- 还会抓"图块库过期"：切片图在、`tileAtlas.json` 里没这个名字 = 你改了素材忘了重跑生成器。

报告落在 `_out/asset_report.json`。

## 10. 常见坑速查

| 症状 | 原因 | 怎么办 |
|---|---|---|
| 改了代码没反应 | 没保存 | `Ctrl+S` 后再 F5；看文件标签有没有小圆点 |
| 双击 `.tscn` 打开是空白 | 打开的是**资源**不是场景，或场景根节点没脚本 | 确认在「文件系统」里双击的是 `scenes/*.tscn` |
| 地图上一块是空的 | 图不存在，运行时静默跳过 | 跑 `verify_assets.gd`，看是哪个名字 |
| 地图整片颜色不对 / 糊成色块 | 图层顺序被改成正序了 | 恢复倒序建节点（`layers.length-1` → 0） |

## 11. 提交与同步（两份拷贝）

### 11.1 为什么有两份

- **C 盘工作副本**：`C:\Users\hal\WorkBuddy\2026-10-24-23-22-43\godot-next` —— 日常改这里，跑得快，不和仓库的历史纠缠。
- **F 盘仓库副本**：`F:\...\世界OL_源码\godot-next` —— Git 仓库在这里，分支 `feat/godot-next`。

### 11.2 同步规则（重要）

**只拷源码、场景、工具、数据、文档；绝对不要拷 `.import` 文件和 `.godot/` 目录。**

原因：`.import` 里记着导入产物的路径和 md5。两台机器/两个 Godot 版本重新导入会改写上万条 `.import`，提交上去全是噪声 diff，把真正的改动埋掉。

同步的最小文件清单就是：`scripts/`、`scenes/`、`tools/`、`data/`（`compiled` 除外时看情况）、`assets/tilesets/`、`AGENTS.md`、`GDD-重做方案.md`、`开发指南.md`。

### 11.3 F 盘副本第一次跑验收前

新检出/刚 clone 的工程里没有 `.godot/`（被 gitignore 了），意味着**没有导入缓存**。这时 `load("res://assets/map_merged/xxx.png")` 会返回 `null`，`verify_world_map` 会报两条假失败：

- 「带偏移帧用 sourceW/H 逻辑包围盒 (0.0, 0.0)」
- 「本图缺帧时从别的图集补回」

**处置**：跑一次导入，等它跑完（约 4~5 分钟），两条立刻转绿。

```bat
"E:\Godot_v4.7.2-stable_win64\Godot_v4.7.2-stable_win64_console.exe" ^
  --headless --path . --import
```

**别去改渲染代码**——这是环境问题，不是代码缺陷。

### 11.4 提交信息怎么写

这个仓库的习惯是"说清为什么，不只说改了什么"：

```
feat(godot): 地图改 TileSet/TileMapLayer，角色动画改 SpriteFrames

把「字符串查文件 + 每帧即时绘制 + 手写计时器」换成引擎原生结构，画面零变化。

- 地图：206 张切片图烘成共享 TileSet，920 图块 + 1164 镜像变体
- WorldMap 改为「一个原版图层 = 一个节点」
- 修掉：图层节点写死 NEAREST 会差 3.6% 像素 → 改 PARENT_NODE

验收：同分辨率截图逐像素比对，6 张图全部 0 像素差。
```

三段够用：**做了什么 → 为什么 → 怎么验证的**。

## 12. 练手任务（从易到难）

每个任务都写了"改哪、怎么验证、坑在哪"。**做完一个再下一个**，别跳。

### 任务 1：改一句界面文案（10 分钟）

- **改哪**：打开 `scenes/CharacterScreen.tscn`，在「场景」面板找到 `Margin/Root/Header/Hint` 节点，检查器里改 `Text`。
- **验证**：F5，看顶部提示变了。
- **坑**：如果之后要重跑 `build_scene.gd`，这处手改会被覆盖。想永久生效就同时改 `tools/build_scene.gd` 里对应那行。

### 任务 2：给角色屏加一个快捷键（20 分钟）

- **目标**：按 `B` 直接进装备屏（`E` 已经有了，换个键练手）。
- **改哪**：`scripts/CharacterScreen.gd` 里找 `KEY_E` 所在的那个 `match`，加一个分支：
  ```gdscript
  KEY_B:
      _on_equip()
  ```
- **验证**：F5，按 `B` 能进装备屏。
- **坑**：这个工程用 `physical_keycode` 判断按键（不是 `keycode`），这样中文输入法不会吞键。跟着现有写法抄。

### 任务 3：给地图编辑器加一个按钮（1 小时）

- **目标**：在地图编辑器左侧加一个「跳到 100 号地图」按钮。
- **改哪**：`tools/map_editor/MapEditor.gd`，在 `_build_ui()` 里参照现有的 `solo_check`（约 610 行）加一个 `Button`，`pressed` 连到载入 100 号地图的函数。
- **验证**：启动编辑器，点按钮，地图切过去。
- **坑**：左侧面板套了 `ScrollContainer`，新控件要加在里面的 `VBoxContainer` 上，否则会被裁掉。

### 任务 4：接一个音效（2 小时，第一次碰音频）

- **背景**：`assets/music/` 里有 76 个音频文件，**一个都没接**。
- **目标**：点任何按钮有"咔"一声。
- **做法**：
  1. 新建 `scripts/Audio.gd`，写一个 `play_sfx(name)`：维护 8 个 `AudioStreamPlayer` 轮着用（避免同时播放时互相打断）。
  2. 在 `project.godot` 的 `[autoload]` 里加一行 `Audio="*res://scripts/Audio.gd"`（或在「项目设置 → Autoload」里加）。
  3. 在角色屏的按钮 `pressed` 里调 `Audio.play_sfx("click")`。
- **验证**：F5，点按钮有声音。
- **坑**：`assets/music` 里是 76 个 mp3，Godot 4 原生支持，`load("res://assets/music/xxx.mp3")` 直接能用；但 `AudioStreamPlayer` 必须 `add_child` 进场景树才会发声，光 `new()` 不响。

### 任务 5：做一个 NPC 对话气泡（半天到一天，综合练习）

- **目标**：在地图上点一个 NPC，头顶冒出他的一句台词。
- **涉及**：
  - `WorldMap.gd`：NPC 的坐标和点击命中（现在 NPC 是 `Sprite2D`，可以加 `Area2D` 或手算矩形）。
  - `NpcInfo.gd` / `GameData.gd`：拿 NPC 的台词字段。
  - 新建一个 `Label` 或 `PanelContainer` 作为气泡，跟随 NPC 坐标。
- **验证**：进地图，点 NPC，气泡出现；走开或点别处，气泡消失。
- **坑**：UI 面板要放在 `CanvasLayer` 里并设 `layer` 足够高，否则会被世界坐标的精灵盖住（NPC 编辑器就踩过这个坑，见 `tools/npc_editor/README.md`）。

## 13. 术语表

| 词 | 意思 | 在这个工程里的例子 |
|---|---|---|
| **节点 / Node** | 场景里的一个单元，有类型、有属性 | `WorldMap`、`Player`、`Sprite` |
| **场景 / Scene** | 一棵节点树，存成 `.tscn` | `scenes/WorldScreen.tscn` |
| **脚本 / Script** | 挂在节点上的 `.gd` 文件 | `scripts/WorldMap.gd` |
| **Autoload** | 全局单例，游戏启动即创建 | `ScreenState` |
| **信号 / Signal** | 节点发出的广播，别的节点可订阅 | `state_changed`、`pressed` |
| **资源 / Resource** | 存在磁盘上的数据块 | `.tres`、`.png`、`.tscn` |
| **TileSet** | 图块库：把一张图切成格子并编号 | `assets/tilesets/map_ground.tres` |
| **TileMapLayer** | 按网格铺 TileSet 图块的节点 | `Layers/Layer3_tiles` |
| **SpriteFrames** | 一组动画帧的集合 | `Player/Sprite` 里的 `idle`/`walk` |
| **AnimatedSprite2D** | 会播放 SpriteFrames 的精灵节点 | `Player/Sprite` |
| **AtlasTexture** | 从一张大图里裁一块当纹理 | 道具图标 |
| **`res://`** | 工程根目录（只读，打包进 exe） | `res://scenes/...` |
| **`user://`** | 用户数据目录（可写，不打包） | 三个存档 JSON |
| **headless** | 无窗口运行，用于跑脚本/验收 | `--headless --script ...` |
| **verify_*.gd** | 自检脚本，失败退出码非 0 | `tools/verify_world_map.gd` |
