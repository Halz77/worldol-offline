## 1. 先搞清楚「哪份数据是真身」

| 数据 | 路径 | 作用 | 谁在读 |
|---|---|---|---|
| **地图视觉** | `assets/map/<id>.json` | 尺寸、tile 定义、图层、物件、阻挡 | `WorldMap.load_map()` 运行时**直读** |
| 地图元数据 | `data/compiled/worldMaps/<id>.json` | 名字、w/h、出生点、NPC 数、有无图集 | 地图列表 / `spawn` |
| **索引（UI 名字源）** | `data/compiled/index.json` → `domains.worldMaps` | `ids` / `count` / **`names`** | `GameData.name_of()`、下拉框 |
| NPC | `data/compiled/npcs/<mapId>.json` | NPC / 怪物 / 传送点，**格子坐标** | `WorldMap._build_npcs()` |
| 贴图 | `assets/map_slice/<name>.png`、`assets/map_merged/<id>.png+json` | tile 层 / 物件层来源 | `WorldMap._resolve()` |
| 怪物 / 编队 | `data/compiled/monsters/<id>.json`、`groups/<id>.json` | 战斗数值与编队 | 阶段 4 战斗 |

> **⚠ 重要现状**：本工作区里 `compile-game-data.mjs` 和 `godot-import.mjs` 都不存在了（GDD 记录过它们跑过）。
> 因此 `assets/` 与 `data/compiled/` 目前是**不可再生的快照**——改了就是终态，也不会被重跑覆盖。
> 这刚好适合「直接编辑」，但**改之前先备份 / 先 git commit**。

## 2. 三种编辑方式的对比（先选路线）

| 方式 | 一次性成本 | 日常效率 | 风险 | 适合 |
|---|---|---|---|---|
| **A. 专用 Godot 地图编辑器（推荐）** | 1–2 天（查看/画笔/阻挡），再加 1–2 天（物件/新建/撤销） | 高：可视化、所见即所得、F5 立刻验证 | 低：沿用原 JSON，294 张图当天就能改 | 长期做内容 |
| B. 迁移到 `TileMapLayer` + `TileSet`，用 Godot 原生编辑 | 3–5 天（转换器 + 反向导出 + 图层语义重建） | 最高（地形笔刷、动画 tile、原生面板） | 中高：292 个图集要转 TileSet；半透明叠加层/物件层语义要重造；与上游格式脱钩 | 决定「以后只认 Godot 格式」时 |
| C. 手改 JSON / 写批量脚本 | 0 | 低 | 中：2500 格肉眼改不现实；一次写错没有撤销 | 1–2 格微调、批量替换资源名 |

**推荐 A**。原因很实际：

1. 运行时读的就是 `assets/map/<id>.json`，编辑器保存后 **F5 立刻生效**，不需要导入、不需要重编译。
2. 294 张图是现成的，A 方案第一天就能改；B 方案要先写转换器，且 4 张合成图、9 层结构、旋转物件都会在转换时掉信息。
3. 回合制的需求是「加路、加传送、加怪、加房」，不是「画大面积自然地形」；A 完全够用。

B 方案的正确用法是**只做运行时预烘**（P1 第 6 项）：编辑仍写 JSON，发布前把 JSON 烘成 `TileMapLayer` 提性能。这样两头都不丢。

## 3. 推荐的地图编辑器（方案 A）怎么搭

### 3.1 实际目录（第一版已落地）

```
tools/map_editor/
  MapEditor.tscn      入口场景（正常窗口跑，不做 @tool 插件，方便断点调试）
  MapEditor.gd        主控：载入 / 图层 / 调色板 / 画笔 / 撤销 / 校验 / 保存 / 快捷键
  MapOverlay.gd       叠加层：阻挡红块 / 格线 / 悬停格 / 出生点（画在 MapRoot 之上）
  README.md           操作、快捷键、保存行为、第一版边界
tools/verify_map_editor.gd   验收（只在内存里改，不写真实 assets/map）
```

启动方式（不进游戏主流程）：

```bash
Godot_v4.7.2-stable_win64_console.exe --path godot-next res://tools/map_editor/MapEditor.tscn
```

`WORLDOL_MAP=<id>` 可以指定初始地图（默认 4）。

### 3.2 第一版做了什么（已落地）

- 打开地图：搜索框按名字/id 过滤 + 294 张下拉列表；载入时整图适配可见区域。
- 相机：中键平移、滚轮以鼠标为锚点缩放、`F` 整图适配。
- 图层列表：显示 `layers[i]`（类型 / 格数 / 物件数）。
- **tile 画笔**：调色板把 `tileList` 每一格展开成按钮，预览方式与 `_draw` 完全一致
  （图集比格子大时按 `col/row` 裁子帧）；左键画、右键擦（写 `255`）。
- **阻挡画笔**：`T`/`B` 切换，左键置 bit0、右键清 bit0，半透明红块叠加显示。
- 撤销：一次拖动 = 一步（首次改动时 `duplicate()` 当前层 `data` 或 `blocks`），上限 50 步；
  撤销后原地恢复数组内容，`WorldMap` 不需要重新 `load_map`。
- 保存：写 `<id>.json.tmp` → 原文件备份到 `_out/map_backups/<id>.json.bak` → 覆盖；
  保存前校验（§4 的 1/2/3/5 条）+ JSON 数字规范化为 int。
- 合成网格图（814/821/908/914）拒绝保存；`blocks` 整键缺失（450）时保持缺失，只有画阻挡才创建。

### 3.3 第二版（2026-11-17 已全部落地）

- **物件编辑**：从 `mapFrames.json`（2485 个资源名）搜索，点选为画笔；左键放置
  （吸附 8px，宽高取帧 `sourceW/sourceH`）、点已有物件选中拖动、`R` 循环变换 0–7、
  `Del`/右键删除。写在物件层 `type==3`，格式 `[2,src,x,y,w,h,tr]`；kind 3/4 的 NPC/模型不选中。
- **图层增删**：`+图层` 追加到 `layers` 末尾（= 最底层）；`-图层` 删当前层，至少留一层。
- **新建 / 复制地图**：以当前图为模板复制，填新 id（默认 max+1），写 `assets/map/<id>.json`
  并在 `data/overrides/maps.json` 登记元数据（不碰 index.json 快照）。NPC 分片/图集不复制。
- **批量替换资源名**：所有 tile 定义 + 物件里叫某名字的全换成另一个（`106_1`→`304`）。
- **改尺寸**：三种策略（保留左上 / 居中 / 扩边），同步重排每层 `data` + `blocks`，物件坐标按 center 平移。
- **改名**：写 `data/overrides/map_names.json`（见 §6 方案 A，已实现）。
- **保存前校验** + 独立的「校验」按钮：§4 硬约束 + 索引上限 + 物件不越界 + 传送目标存在。
- 以上结构操作全部可 `Ctrl+Z` 撤销：**整 cfg 快照 + 递归原地恢复**（保持 WorldMap 持有的
  数组引用不失效——这是第一版 tile/block 撤销原则的推广）。
- 左侧栏改为可滚动（第二版控件多，调色板固定 170px，不再 `EXPAND_FILL` 吃满高度）。

**仍未做**（不是编辑器职责）：NPC / 传送 / 商店 / 任务的编辑（`data/compiled/npcs` 的事）；
改单个物件精确坐标（只能 8px 吸附拖动，精调改 JSON）；删除地图时反向清理别处的 `jumpMapID`。

### 3.4 实现要点（少踩坑）

- 编辑器和运行时**共用同一份绘制代码**：编辑器直接复用 `WorldMap` 节点，`cfg` 是同一个 Dictionary 引用，
  画笔只改 `layers[li].data[i]` / `blocks[i]` 然后 `queue_redraw()`；绝不重建纹理缓存、不重复 `load_map`。
  调色板预览按 `_draw` 的裁切规则（`col/row` 子帧）生成，避免「画笔图标和画上去的不一样」。
- 编辑时禁掉 `_prefill_holes()`（补洞只该在「显示」时做），否则你会在编辑器里看到虚构的地面，越改越糊涂。
- 坐标两套别搞混：**tile / NPC 用格子坐标**，**物件用像素左上角**；玩家位置用像素，格子中心是 `(gx+0.5)*tW`。
- 保存时保留未知字段（编辑器的数据模型用 `Dictionary` 透传，不要只挑认识的键重写）。

## 4. 改地图必须遵守的 8 条硬约束

| # | 约束 | 违反后果 |
|---|---|---|
| 1 | `mW % tW == 0`、`mH % tH == 0` | `WorldMap` 用整除算 `_cols/_rows`，余数会被丢掉 |
| 2 | `blocks.size() == cols * rows`（450 号图整个 `blocks` 键缺失 = 全可走；编辑器只在画阻挡时补 `0`） | 越界判定失效（`is_blocked_px` 会 return false 放行） |
| 3 | 每层 `data.size() == cols * rows` | tile 错位、整层不画 |
| 4 | **图层数组是倒序绘制**：`layers[0]` 在最上层，新增图层 append 到末尾 = 最底层 | 地面盖住房子 |
| 5 | **tile 索引只有 1 字节**：`data[i] & 255`，`255` = 空格 → `tileList` 最多 **255 条** | 索引回绕，画错图块 |
| 6 | `tiles` 定义是 `[图名, 变换, 横格数, 纵格数]`，展开顺序先列后行；**只在末尾追加** | 从中间插入会让全图索引整体位移 |
| 7 | 物件是 `[kind, src, x, y, w, h, transform]`，`x/y` 是**像素**左上角；kind `2`=贴图，`3/4`=模型/NPC | 物件错位/拉伸 |
| 8 | 别把 `assets/map_bg/<id>.jpg` 当地图底图 | 那是 160×100 的场景切换模糊图 |

**tile 余量参考（实测）**：`tileList` 平均 105 条、最多 **246 条**（地图 459）；有 1 张图 ≥230 条。
所以「随便加新图块」在个别图上会撞上限——先用编辑器看剩余额度（`255 - 当前 tileList 数`），不够就复用同类 tile 或合并图集。

**图层数参考**：平均 5.6 层、最多 9 层（地图 11）。加层没有硬上限，但每层都要 `cols*rows` 的 `data`。

## 5. 增 / 删 / 改地图

### 5.1 新增一张图

1. **选 id**：现有最大是 **9569**，建议新图用 `10001+`。
2. **建视觉文件**：`assets/map/<新id>.json`，从一张同尺寸模板复制，改 `mW/mH/tW/tH`，重设 `blocks` 与每层 `data`（全 `255` = 空格）。
3. **建元数据**：`data/compiled/worldMaps/<新id>.json`（名字、尺寸、`spawn`、`npc_count` 等）。
4. **登记索引**：`data/compiled/index.json` 的 `domains.worldMaps.ids / names / count` 三处都要加。
   > 手改这个 158 KB 单行 JSON 很容易出错，建议在 `data/overrides/maps.json` 里登记，由 `GameData` 合并（见 §6，同一套机制也管改名/隐藏）。
5. **接通世界**：在某个城镇 NPC 上加 `jumpMapID=[新id]`、`jumpMapGx/Gy`、`topic="前往试炼场"`，否则玩家走不进去。
6. **放内容**：`data/compiled/npcs/<新id>.json`（NPC / 怪 / 传送点），`assets/map_slice` 里贴图按名字引用。
7. **验收**：`verify_world_map.gd` + 手动走一遍传送落点。

### 5.2 删除一张图

**不要直接删分片**——`index.json` 和别的图的 `jumpMapID` 都会断。

1. 在 override 里标 `hidden`（UI 列表过滤 + `load_map` 拒绝），分片保留。
2. 用脚本扫一遍所有 `jumpMapID`，清掉指向它的传送点。
3. 确认没人引用后，才删 `assets/map`、`worldMaps`、`npcs` 分片并同步 `index.json`。

### 5.3 修改已有图

- **改尺寸**：`mW/mH` 变了，`blocks` 和**每一层** `data` 都必须按新 `cols*rows` 重排。编辑器要给三种策略：保留左上角 / 居中裁剪 / 扩边填充。
- **改地面**：tile 画笔写 `data[i]`；整片替换用「矩形填充」。
- **改阻挡**：只动 `blocks[i]` 的 bit0，别动其它位（将来要用）。
- **改物件**：只动对应图层的 `obj` 数组；旋转用 `transform 0–7`（语义见 `AGENTS.md` §3，别自己推）。
- **换贴图**：同名覆盖 `assets/map_slice/<name>.png` 立即生效；**新增** PNG 要先跑一次 `--headless --path godot-next --import`。

### 5.4 加怪 / 加 NPC / 加传送（数据链）

```
传送：NPC.jumpMapID[] → 目标地图 id，jumpMapGx/Gy → 目标格
遇敌：NPC.battleID[] → groups/<编队id>.monsters[10] → monsters/<怪物id>
商店：NPC.menuShop[] + shopID[]
任务：NPC.missionData / missionGroupID
```

例（地图 11「魔教剑客」）：`battleID:[2033]` → `groups/2033` → `monsters:[0,0,2041,0,2041,0,2041,0,2041,0]`（魔教刀客 ×4）。
全库现状：**1146 个 NPC 带 battleID，292 个去重编队，277 个能解析到 `groups` 分片**。
新增怪 = 在 `monsters` 加一条 + 在某个 `groups` 编队里占一个槽 + 给地图 NPC 的 `battleID` 指过去。

## 6. 地图重命名（关键：名字有**三层**）

| 层 | 位置 | 谁在用 | 改了会怎样 |
|---|---|---|---|
| **1. UI 显示名** | `data/compiled/index.json` → `domains.worldMaps.names["4"]` | `GameData.name_of()` → `WorldScreen.gd:108` 标题、`:62-75` 下拉框 | **只改分片里的 name 不会变**——这是最容易踩的坑 |
| 2. 分片名字 | `data/compiled/worldMaps/<id>.json` 的 `name` | 读分片的地方 / 数据校验 | 与索引不一致时，两个界面显示不同名字 |
| 3. 地图库/区域名 | `data/compiled/mapList/<id>.json`、`areas/<id>.json` | 阶段 5 的分类导航 | 与上面不同步时，同一张图在不同界面叫不同名字 |

### 方案 A（推荐，已实现）：加一层 override，一处改名全局生效

> 地图编辑器的「改名」按钮就是自动写这份文件，不用手改 JSON。
> `GameData.name_of()` 已接入：`map_names.json` 优先，其次是 `maps.json` 里新建地图的 `name`，
> 最后才是 index.json 快照。手改也行，格式如下。

新建 `godot-next/data/overrides/map_names.json`：

```json
{
  "4": "太阳城",
  "16": "后山小径",
  "11": "镇妖塔（一层）"
}
```

在 `GameData.name_of()` 最前面查它（约 10 行代码）：

```gdscript
const OVERRIDE_NAMES = "res://data/overrides/map_names.json"

func name_of(domain: String, id) -> String:
    if domain == "worldMaps":
        var ov = _json(OVERRIDE_NAMES)
        if ov is Dictionary and ov.has(str(int(id))):
            return str(ov[str(int(id))])
    # ...原有逻辑
```

优点：不碰上游快照；重导入/重编译不会被覆盖；想回滚删一行即可；`search()` 想同步的话也读同一份表。

### 方案 B：直接改两处（一次性）

1. `data/compiled/worldMaps/<id>.json` 里的 `name`
2. `data/compiled/index.json` → `domains.worldMaps.names["<id>"]`

两处必须一起改，否则就是你「改了名但界面没变」的原因。适合只想改 1–2 张、且不打算再动的情况。

### 方案 C：改源数据再重编译（当前不可用）

名字的源头是 `世界online_原版单机/data/official-v305.json`，正常流程是改源 → 跑 `compile-game-data.mjs`。
但该脚本**已不在工作区**，所以现在只能走 A 或 B。

> 附带提醒：UI 标题是 `"%s  #%d" % [名字, id]`（`WorldScreen.gd:108`），
> 如果不想让玩家看到 `#4`，改名时顺手把这行格式化去掉编号，或加一个「显示调试编号」开关。

## 7. 改完怎么验收

```bash
# 1) 全量地图断言（294 图 / 1939 NPC / 障碍 / 行走）
Godot_v4.7.2-stable_win64_console.exe --headless --path godot-next --script res://tools/verify_world_map.gd

# 2) 正常窗口截图核对（改完一定要看画面，不能只信断言）
set WORLDOL_CAPTURE=1
set WORLDOL_MAP=<改过的id>
Godot_v4.7.2-stable_win64_console.exe --path godot-next res://scenes/WorldScreen.tscn --quit-after 90
# 产物：godot-next/_out/world_screen.png

# 3) 排查单块色块/物件（见 AGENTS.md 调试开关）
set WORLDOL_GRID=1
set WORLDOL_ONLYLAYER=<层号>
set WORLDOL_SKIP=<资源名>
```

建议给编辑器加一个「保存前校验」清单（§4 的 1/2/3/5 条 + 索引 ≤ 254 + 物件不越界），
把上面这些错误挡在存盘之前，比事后看截图快得多。
