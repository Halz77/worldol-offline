## 0. 一句话结论

**画面已经和原版对齐，缺的是「游戏地图」这层骨架**：连通、交互、遮挡、遇敌。
阶段 3 交付的是「渲染正确的看板」；标准回合制需要的是「可走、可谈、可打、可存档的场景」。

所以本方案的优先级不是继续修贴图，而是补玩法骨架；渲染层的改动只在**挡住玩法**时才做（首要是 Y 排序）。

## 3. 渲染层问题（P1：只在挡住玩法或明显掉帧时处理）

| # | 问题 | 证据 | 后果 |
|---|---|---|---|
| **B1** | **没有 Y 排序 / 遮挡**：人物永远压在所有树、房子、墙上 | 整图在 `WorldMap._draw()` 一次画完；`Player` 是兄弟节点且在其后（`scenes/WorldScreen.tscn:21-25`） | 走不到树后面，2D 地图最基本的空间感缺失 |
| **B2** | 逐格 `draw_texture_rect_region`，无相机裁剪、无批次合并，也没用 `TileMapLayer` | `WorldMap.gd:301-438` | 最大图 2500 格 + 3935 物件/帧；加战斗特效后会更吃紧 |
| **B3** | `_atlas_images` 只增不减（跨图集补帧时把整张图集读成 Image 常驻） | `WorldMap.gd:39, 952-962` | 272 张图集 14.5 MB PNG，解成 RGBA 是几十上百 MB；逛图必涨内存 |
| **B4** | 补洞逻辑是启发式 + 硬编码，只为少数图服务 | `_fill_broken_maps` 为空、`_replace_srcs=["106_1"]`、`_tone_down_map=100`、`_replace_ground{100:"304"}`（`WorldMap.gd:529-543`） | 每次载图都遍历全图并逐像素采样；换素材后行为不可预测 |
| **B5** | 碰撞只有脚下一个点；人物 90×100，脚底比 `position` 低约 15px | `is_blocked_px()`（`WorldMap.gd:277-285`）+ `WorldPlayer.gd:128` | 能明显「站进」下方墙里；无半径、无贴墙滑动 |
| **B6** | `blocks` 只有 bit0，没有水/悬崖/单向/遮挡语义 | 地图 4 实测 | 以后要加地形差异得改数据格式 |
| **B7** | 相机没有缩放/死区/战斗转场 | `WorldScreen.gd:151-172` | 进战斗没有推镜，地图缩放不可调 |
| **B8** | 每帧遍历全部 NPC 刷名字标签 | `update_labels_near()` 在 `_process` 中 O(n)，最大 3935 个 | 大图上无谓开销 |
| **B9** | NPC 造型来源有冲突：先试 `sprite_fragment/<icon1>.png`（**图集**）再试 model | `WorldMap.gd:191-198`；实测 `icon1=5006` 两者都存在 | 会把整张零件表当 NPC 画出来（需统一走 `SpriteComposer`） |

## 5. 目标架构（一张图 = 一个场景容器）

```
MapController      载图 / 传送 / 落点 / 遭遇判定 / 战斗胜负回调
├─ MapView         地面与物件渲染（先沿用 _draw，后续可预烘）
├─ EntityLayer     YSort：玩家 + NPC + 怪物 + 传送点，共用一套排序
└─ Interact        靠近高亮 → E 触发 → 对话 / 传送 / 商店 / 战斗
```

分四层的原因：**玩法（交互/传送/遇敌）与表现（贴图/排序/相机）解耦**，
以后换成 TileMap 或预烘 chunk 时，玩法层不用改。

## 6. 路线（按「每步都能玩」切）

### P0 · 骨架（约 1 天，建议先做）

| 顺序 | 任务 | 数据来源 | 验收 |
|---|---|---|---|
| 1 | 传送与出入口：交互 → 切图 → 落到目标格 + 朝向 | `jumpMapID/jumpMapGx/jumpMapGy/topic` | 89 个目标全部可达、无死链；传送后坐标正确 |
| 2 | 交互系统：靠近气泡 + `E` | `talkDetail/welcome` | 城镇 NPC 能对话 |
| 3 | 明雷遇敌：接触怪 → 带 `groups` 进战斗 | `battleID` → `groups/<id>` → `monsters/<id>` | 地图 11 的「魔教剑客」能打起来 |
| 4 | Y 排序 / 遮挡 | — | 能走到树/房子后面 |

### P1 · 工程与体验

5. 碰撞改成脚下圆/胶囊（半径 ~10px，脚点下移 15px），支持贴墙滑动；`blocks` 预留 bit 语义。
6. 预烘地图（JSON → `TileMapLayer` 或 chunk 纹理），把补洞/压暗固化进数据，删掉 `_tone_down_map` / `_replace_srcs` / `_fill_broken_maps`。
7. `_atlas_images` 加 LRU / 只取需要的帧。
8. NPC 造型统一走 `SpriteComposer`，修 `icon1` 图集冲突；标签只维护视野内节点。
9. 分类导航（城镇/野外/副本 + 等级区间，接 `areas`/`mapList` 简介）+ 小地图 + 区域名 HUD + BGM。

### P2 · 回合制专属

10. 战斗转场：踩怪 → 相机推近 + 闪白 → `BattleScreen`；胜利回调地图（怪消失或刷新计时）。
11. 暗雷：新增 `data/compiled/encounters`（地图 → 遇敌率 / 怪物组权重 / 等级区间），走 N 步判定一次。
12. 存档：`map_id + 像素坐标 + 朝向 + 队伍 + 背包 + 任务`，单文件 + 版本迁移。

## 7. 建议的最小切片

- **切片 A（半天）**：传送 + `E` 交互 + Y 排序 → 地图立刻「像一个游戏」。
- **切片 B（接阶段 4）**：一张冒险图的明雷怪 → 战斗屏 → 胜利回地图、掉落入包。
- **切片 C**：预烘地图 + 内存/碰撞整修（趁着战斗屏还没堆复杂，成本最低）。

## 8. 验收补充建议（改完地图/玩法后跑）

在 `tools/verify_world_map.gd` 增加：

1. 所有 `jumpMapID` 目标 id 都在 `worldMaps` 中存在；传送 NPC 的目标坐标在地图范围内。
2. 所有 `battleID` 引用的编队 id 在 `groups` 中有分片（当前 277/292，其余记为白名单）。
3. `groups/<id>` 引用的 `monsters` id 都存在（404 个怪物分片）。
4. Override 生效：改名/隐藏/新增地图后列表与标题一致。
5. 新增地图能被 `load_map` 打开，且 `blocks.size() == cols*rows`。
