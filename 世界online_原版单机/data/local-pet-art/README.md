# 自制宠物 · 贴图素材

这个目录放**你要做的宠物贴图**和它的构建配置 `reskin.json`。

`data/local-pets.json`（模板/数值）和这里（贴图）是两回事：
- `local-pets.json` —— 宠物叫什么、几阶、数值多少、用哪个外观编号
- `local-pet-art/` —— 外观的图本身 + 换皮配置

## 三步流程

1. **选底模**：从现有 136 个有精灵的宠物里挑一个当动画基底（朝向、动作、攻击帧全靠它）。
   参考包（底稿 + 三份说明）可以随时重跑生成：
   `node tools/export-pet-reskin-templates.mjs`（默认写到
   `<项目根>/FileRecv/MobileFile/pet-reskin-templates/`，`--out` 可改）。
   先看 `00-尺寸清单.md`：它标了每张贴图**要不要画** —— 几千个 model 共用的阴影/光效
   一律不用画，真正要动手的通常只有 1~2 张（加头像 2~5 张）。
2. **画贴图**：文件名里的 `slot<数字>` 就是底模 json 里 `files` 的下标，也是
   `reskin.json` 的 `replace` 要填的数字。照**布局图 SVG 里的红框**画，**像素级一致**。
   阴影之类的小件不用管 —— 那是几千个 model 共用的，构建时原样保留。
3. **写 `reskin.json` 并构建**：

```json
{
  "fragmentIdStart": 40000,
  "modelIdStart": 60000,
  "entries": [
    {
      "key": "冰霜幼龙:4",
      "baseModel": 504,
      "baseHead": 503,
      "replace": { "model": [0], "head": [0] },
      "textures": { "model": ["冰霜幼龙-body.png"], "head": ["冰霜幼龙-head.png"] }
    }
  ]
}
```

```
node tools/build-pet-reskin.mjs --check   # 先验尺寸，不写文件
node tools/build-pet-reskin.mjs           # 构建
```

构建完会打印 `冰霜幼龙:4 → model:60000 headIcon:60001`，把这两个号填进
`data/local-pets.json` 里那只宠物的 `baseline.model` / `baseline.headIcon`。

## 先看清一件事：贴图是「部件拼图」，不是一只宠物

一张贴图（比如 118×80）里面排着**十几个部件**，渲染时按
`[贴图下标, 部件号, x偏移, y偏移, flag]` 把若干部件拼成一只完整的宠物。

所以你要画的是**这些部件**，而且每个部件必须待在自己那一格 ——
位置、尺寸差一个像素，拼出来的角色就散架。

每个底模的部件布局已导出到 `pet-reskin-templates/<底模>/布局图-fragXXXX.svg`
（浏览器打开就能看，**红框 = 动画真正用到的部件**）和 `layout-fragXXXX.json`。
`01-部件布局.md` 里有完整表格，标了哪些部件是动画真正用到的（没用到的可以先不画）。

注意：贴图里没有图集 json 的那些是**单部件图**（整张图就是 1 个部件，sub 恒为 0），
照整张画即可；参考包的说明里会写清楚。

## 素材硬约束

| 项 | 要求 | 违反会怎样 |
|---|---|---|
| 格式 | PNG | JPG 没有透明通道，直接不行 |
| 背景 | 必须透明 | 会盖住地图 |
| 尺寸 | **整张贴图像素级等于底模** | 构建**直接报错挡住**，不会让你做错 |
| 部件位置 | 每个部件待在布局表指定的格子里 | 不报错，但拼出来的角色会散架 |
| 内容 | 只画主体，不要阴影/文字/边框 | — |

## 风格：不是只能像素风，但基本会被推向像素风

**技术上没有风格限制** —— 只要满足上面的硬约束，任何 PNG 都能进去。
真正把你推向像素风的是这三件事：

1. **画布拉不开**：部件普遍只有 13×22 ~ 36×38 px，几百个像素的格子，
   再好的细节也没地方放。
2. **原版是纯硬边**：实测原版贴图 alpha **只有 0 和 255 两个值**（索引色 + tRNS），
   完全没有半透明像素 —— 也就是说原版美术一根羽化边缘都没用。混进去会明显突兀。
3. **半透明未经验证**：我无法在 Node 里确认引擎怎么处理羽化边缘（可能正常，
   也可能出现黑边/白边）。这是唯一的未知风险。

| 风格 | 能做吗 | 说明 |
|---|---|---|
| 硬边像素风（原版同款） | ✅ 推荐 | 零风险，和现有宠物最协调 |
| HD 像素风（更细腻、色阶更丰富） | ✅ 推荐 | 仍是硬边，但看着更精致，现代独立游戏常用 |
| 手绘 / Q 版描边 | ✅ 可试 | **必须关掉抗锯齿、用硬边笔刷**，小尺寸下其实和像素风差别不大 |
| 带羽化/抗锯齿的高清图 | ⚠️ 不推荐 | 缩到 36×38 基本是一坨，边缘还有未知风险 |
| 写实插画 / 照片 | ❌ | 尺寸决定了一切，别费这个劲 |

**给非索引色的图会怎样**：构建时会打印一条 ⚠ 警告（说明底模是什么色型），
**但不会阻止你** —— 尺寸和布局是硬约束，色型是「未知风险」。
真想用非硬边风格的话，建议**先做一只试包在手机上看效果**，确认没问题再批量做。

**颜色数量**：原版索引色调色板实测 29~75 色（上限 256）。颜色别太碎，
渐变太多转索引色时会出现色带。

## 换皮为什么只要改一个数字

model json 里 `frames` 的 `fi` 是 **`files` 数组的下标**，不是贴图编号：

```
files:  [12017]                    ← 贴图编号
frames: {0:[[0,sub,x,y,flag],...]} ← fi=0，指 files[0]
anis:   [{id:0},{id:2}]            ← 待机 / 攻击
```

所以把 `files[0]` 从 12017 换成新编号 40000，`frames` 和 `anis` **一个字节都不用动** ——
朝向、动作、攻击帧全部白送。这也是为什么换皮只要 1~2 张图，而不是重画 300 帧。

## 注意

- `client/` 不入库（见 .gitignore），构建产出的贴图不进 git。换机器后重跑
  `node tools/build-pet-reskin.mjs` 就能重建。
- 只丢了图、登记表还在也没关系：资源登记时会检查文件是否存在，缺图就跳过，
  那只宠物只是沿用底模外观，不会让游戏起不来。
