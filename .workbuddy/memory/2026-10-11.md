产出：`世界online_原版单机/架构评审-20261011.md`（含实测数据与 file:line 证据）。

### 实测结论（下次别重复测）
- `import('./server.mjs')` 热盘 **1,714 ms**、**RSS 528 MB**、heapUsed 302 MB；
  **冷盘 60 秒**（161 MB JSON + 148 MB 客户端首次触盘）。
- `import('./lib/store.mjs')` 一个就 890 ms，RSS 43 → 318 MB —— 它牵进整张数据图。
- 各 JSON 解析后常驻：content-library 48 MB、official-v305 29 MB、skill-progression 26 MB、
  career-skill-directory 19 MB、recorded-content 15 MB、recorded-expansion 11 MB…合计 ~160 MB。
- 客户端补丁链（17 个函数）总耗时 **~840 ms**，其中 `patchCombatLimits` 独占 **720 ms**（全量正则）。
- 仓库根残留 **78 个** `test-captured-expansion-*` / `test-save-check-*` 临时目录（624 KB）。

### 架构事实（以后别重新推导）
- **没有 git**。整个工程不在版本控制下。
- **补丁链写了两份**：`server.mjs:89-90` 与 `安卓打包/standalone/build.mjs:85-104`，
  注释明写"顺序必须一致"，**没有测试守着**。
- **构建期打一遍补丁、运行期又打一遍**：`build.mjs` 的 VFS 清单里
  `client/<MAIN_PATH>` 指向 `/<MAIN_PATH>.orig`（未打补丁），注释说"server.mjs 还要自己打一遍补丁"；
  也就是每次启动都要重读 4.9 MB 重打全链。约束只写在注释里。
- **改客户端有两个入口且边界不清**：`lib/client-*-patch.mjs`（字符串注入主包）与
  `web/*.js`（额外脚本，index.html 里 23 个 script 隐式排序）。
- `server.mjs` 268 行里：70+ import、20 个内联 `type===` 分支、23 项 HTTP 路由表；
  分派是 20 层 `if(handleX(...))return;` 顺序敏感链（handleGame 必须最后）。
- 协议号裸数字；`analysis/modules/0019.js` 有完整枚举表，但只用来取 4 个常量。
- `data/` 三套"技能/道具目录"并存（official-data / recorded-content / career-skills），
  无血缘文档说明谁覆盖谁。
- 测试：65 文件 / 370 用例，`known-failures.json` 忽略 **47 条**长期失败（"新增失败=0"判定）。

### 做对了的（重构时别误伤）
- `tools/run-tests.mjs`：摘 shim、解析 TAP、按清单忽略、只对新增失败退出 1。
- `SaveStore.save()`：temp → `.bak` → 原子 rename；存档用紧凑 JSON（省一半体积）。
- `native-ui-restoration`：归档原件字节不动，补充只在内存清单上做（测试断言原件 sha256）。
- `android/standalone/shims/`：fs/ws/crypto 换内存实现，一份代码两个平台。
- `replaceOnce()` 匹配失败即抛错，绝不静默跳过。

## 落地建议 1–3 项（用户："先做1和2吧" + 追加第 3 项）

### ① 版本控制
仓库根 `git init`（main）+ `.gitignore`，基线提交 **2bbe512**（789 文件，`.git` 260 MB）。
本地 `core.autocrlf=false`（修复记录.txt / *.cmd / *.ps1 必须保 CRLF）、`core.quotepath=false`。
忽略 ~320 MB：client/、analysis/、node_modules、saves|logs|backups|runtime、
安卓打包/app/www 与 android 的 build/.gradle、*.apk、test-*/、.scratch/。
跟踪 lib/ tools/ tests/ web/ data/ server.mjs 构建脚本与文档。

**坑一**：`.gitignore` **不支持行内注释** —— 只有行首 # 才算注释；
`安卓打包/app/www/   # 说明` 整行会被当成 pattern，结果 10388 个站点文件被误暂存。
**坑二**：unborn 分支上清空索引要用 `git read-tree --empty`；
`git rm -r --cached .` 会以 "use -f to force removal" 拒绝（`git reset` 也不行，无 HEAD）。

### ② 补丁链收敛（第 33 版）
新增 `lib/client-patch-chain.mjs` 作为唯一来源：
`CLIENT_MAIN_STEPS`(23 步) / `CLIENT_BOOT_STEPS`(3 步) / `patchClientMain` /
`patchClientBoot` / `replaceOnce` / `CLIENT_MAIN_PATH`。
`server.mjs` 与 `安卓打包/standalone/build.mjs` 都改成 import 它，各自本地那份 replaceOnce 删掉。
server.mjs 仍保留 16 个 revision 常量 import（/api/status 用），只是不再取补丁函数。
守卫 `tests/client-patch-chain.test.mjs`（8 条）：顺序 deepEqual 钉死、两边都不再自带链、
锚点缺失必抛错、主包 4557839→4564108、boot 35493→35317 且 50ms 定时器被摘。

## 第 35 版 · 运行期跳过重复打链（评审第 6 项的前半）

**问题**：standalone 里主包构建期已打过补丁，但 `build.mjs` 又把 VFS 清单里的主包
指向另一份未打补丁的 `.orig`，于是每次启动重读 4.5MB、重跑全链 —— 实测 **834ms**。

**改法**：`lib/client-patch-chain.mjs` 加 `WORLD_REQUEST_MARKER` + `isClientMainPatched()`，
`patchClientMain()` 开头做幂等判断（源里已有标记就直接返回）；`build.mjs` 不再产出
`.orig`，VFS 直接指向打过补丁的成品。

**实测**：对站点主包调 `patchClientMain` = **0ms**（原版 = 834ms）；站点主包 sha256
逐字节不变；站点里已无 `.orig`。守卫用例 +2 条，共 10 条全绿。
全量 **396 用例全过**。

**注意**：这是**打包运行时**的收益 —— Node 开发路径读的是 `client/` 里的原版，仍会正常打链
（启动仍是 ~1.8s / RSS 566MB）。

**patchCombatLimits 局部化没做**：它用 acorn 全量 parse 后按 AST 精确定位第 56 号模块的
`get`/`addValue`，并校验「2 函数 × 每函数 7 个 case」。退回纯文本会丢掉这层校验、
有误改别处的风险；省下的 700ms 只在开发路径上。要动就应**缩小 parse 范围**
（先轻量扫描定位模块数组切片）而不是纯文本匹配。
