## 第 26 版：美容院造型道具改用用户补齐的真实贴图（一件对一张，发型 29 + 脸型 14）

### 需求
用户自己补齐了脸型/发型图片，放在 `世界OL_源码/` 下的 `face_png_i`、`face_png_o`、
`hair_png_i`、`hair_png_o`（i = 男，o = 女）。要求：塞进美容师（商店 51/52/55）的道具里
当角色贴图，用道具能换发型/脸型；道具数 = 贴图数，多的删掉；序号按实际顺序。

### 关键发现（务必记住）
1. **四份目录里的 PNG 与客户端 `client/assets` 里已有的角色碎片逐像素完全相同**
   （尺寸 + RGBA sha256 比对，56 张全中）。所以并没有"缺图"，要做的只是：
   把道具清单换成这些贴图，并让商店列表直接显示它们。
2. **碎片编号 = SpriteTool 公式**（`analysis/modules/0055.js`；`0056.js` 的 updateHair/updateFace 同源）：
   - 发型碎片 = `0 + 8*style - 7 + 4*gender + color`（gender 0=男 1=女，color 0..3）
   - 脸型碎片 = `1000 + 8*style - 7 + 4*gender`
   实测清单：男发 29、女发 27、男脸 13（样式 2..9,11..15）、女脸 13（样式 3..15）。
   **一件发型道具是性别无关的**（客户端按玩家性别自己挑 4*gender 那段），所以取并集：
   发型 29 件（样式 1-8）、脸型 14 件（样式 2-15）。
3. **客户端资源系统**（`analysis/modules/0132.js` 资源管理器 / `0059.js` 加载器 / `0225.js` MergedBmp）：
   - 资源清单 = `client/v/gd/305.json` 的 `res{groups,resources}` + `url{assets,resource}`；
   - 图集 = `assets/<url>.png`（hash 由 `url.resource.ui['<name>.png']` 给出）
     + 帧表 `assets/data/sheet.json`（一个「JSON 字符串数组」，key = `resource/<url>.json`）；
   - 子键即资源名 → `Tool.getIconByData` 把 `bagIcon` 转成字符串当资源名，所以
     **bagIcon = 图集子键 = 道具编号**，商店列表就显示真图；
   - 资源组必须加载才会注册子键：图集挂到了**每一个** group 上（各界面加载的组不同）。
4. 归档清单 `client/v/gd/305.json` **字节不能动**（tests 断言 sha256），
   所有补充只在内存里生成的那份清单上做（`lib/native-ui-restoration.mjs`，服务端+构建期共用）。

## 第 27 版：造型道具改成原版的「买下即换造型」道具（不再是装备）

### 需求
用户反馈「贴图没问题，但这些不应该是装备，而是一种道具，使用之后角色的脸型或发型
会转变成相应的贴图」。

### 关键发现（务必记住）
1. **原版客户端本来就有这条链路**，只是本地道具编号没落在它写死的判定区间里：
   - `ModelConst.ITEM_ID_HAIR_START=40100 / END=40199`、`ITEM_ID_FACE_START=40200 / END=40249`
   - `isHairItem/isFaceItem` 判的是**道具 ID**，与 type 无关
2. **购买回包状态位 == 2 = 「买下即用」**（主包 `t.onItemShopBuy`）：
   客户端直接 `updateHair(t)/updateFace(t)` + `refreshWorldSprite()`，
   **不进背包、不走装备流程**；状态 0 才是普通购买。回包结构：
   `byte(2) + int(money1) + int(money2) + int(money3) + short(maxBuy) + short(allCount)`。
   12005 **不在** `resultMsg` 集合里（那个集合只装 CG_COUNTRY_*），所以首字节不会被框架吞。
3. **`updateHair/updateFace` 读的是商品的 `icon` 字段**，公式：
   `i=icon-START_HAIR(0)` → 样式 `1+(i-1)/8`、颜色 `(i-1)%8`；脸型 `i=icon-START_FACE(1000)`。
   所以 **icon 直接等于该款造型的男性碎片编号**（= `male`），女性碎片也能用（多出的 +4 被 2 位掩码截掉）。
4. **type 必须保持 12**：只有 `ITEM_CLASS_ARMOR` 分支读 `icon`；
   `ITEM_CLASS_USE_ITEM` 分支从 `reqLv` 开始、**不读 icon**。换成普通道具类型 icon 就丢了。
5. **官方 2505 件道具里没有 40100-40249**（确认过），所以这段是我方补充。

### 改动
- `tools/build-fashion-icons.mjs`：`HAIR_BASE 900101→40101`、`FACE_BASE 900201→40201`；
  每项新增 `icon`（= 男性碎片编号）；REVISION → `fashion-icons-20261010b`
- `lib/local-fashion.mjs`：编号换号段、编码写 `icon`；新增
  `applyHairAppearance/applyFaceAppearance`（复刻客户端位运算）、

- `lib/restoration-service.mjs`：12005 造型道具单独一支（数量必须 1 → 扣铜币 → 改 icon1

- `lib/supply-shops.mjs`：造型道具从补给商店分类与 `coverage(12)` 里排除（否则 908 商店

## 第 30 版：重写游戏内公告（更新内容）

### 需求
用户给了按功能分好的更新清单，要求替换游戏内公告里原有的更新内容，并润色。

### 公告在哪
`web/offline.js` 里 `req(360).default.prototype.applyNotice=async()=>[...]`，
返回值是富文本字符串数组，走 `0014 parseHtml -> 0008 convertDescToTextFlow` 解析。
- 只认游戏自己的颜色标记 `/cRRGGBB … /p`，**不认 HTML**（`<font>` 会原样显示成乱码字符）
- 每个 `/c` 必须配一个 `/p`，否则颜色串到后面的文字
- 配色惯例：FFD700 金黄(大标题) / 00FF00 绿(分类标题) / 87CEEB 天蓝(说明) / FF6666 红(警示) / FFFFFF 白(正文)

### 改动
- 公告正文：原来的「更新内容 / 新增内容 / 问题修复」流水账（编号排到 20 多）
  → 改成 `★ 本次更新 ★` + 【角色】【宠物】【装备与道具】【技能】【外观】【玩法】六个分类
  + `★ 问题修复 ★`（10 条）。开头欢迎语与结尾「严禁商用」保留。
- 版本按钮 v11.1 → v11.2（web/index.html）

### 坑（重要）
**构建后的 `app/www/offline.js` 里中文被 esbuild 转成 `\uXXXX` ASCII 转义**，
所以校验站点/APK 内的公告内容时，直接 `grep '【外观】'` 会误判成缺失。
正确做法是用 Node 提取那段数组再 `eval`，比的是解码后的字符串。

- 标记自检：68 行，`/c` 与 `/p` 逐行配对、颜色均 6 位十六进制，0 异常
- 站点 + APK 双重 eval 核对
