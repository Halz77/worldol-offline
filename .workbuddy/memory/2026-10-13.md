# 第 48 版 · 同日追加：新宠物没进商店 + 宠物幻化后场景里不变

## ① 冰冰没进商店（商店显示旧数量）
服务端算出来就是 147 种、末尾正是冰冰的蛋 30000146，两条路径（supplyDirectory 与 shopItems(918)）
都一致 → 问题是玩家那台设备上拿到的**资料是旧的**。根因是一条四环链：

- data/*.json 不预载、不打包，运行时由 VFS 用**同步 XHR** 现取，URL 常年不带版本号；
- applyBuildStamp() 的指纹只覆盖 index.html / gd.js / 主包 / 305.json 这些**代码与入口资源**
  → 「只改 data/local-pets.json」的构建，指纹与上一版完全相同；
- MainActivity 按这个指纹决定是否清 WebView 缓存 → 指纹没变就**不清** → HTTP 缓存喂旧资料；
- 结果：APK 里确实有冰冰，商店就是不出现。

改法（三处）：

1. `安卓打包/standalone/build.mjs` 新增 hashTree()，把 data/**（191 个文件，约 1.2~1.5 秒，
   readSync 分块读、不把 30 MB 整个读进内存）计入构建指纹 —— 资料一变指纹就变。
2. `安卓打包/standalone/shims/vfs.mjs` 的 syncFetchText() 在 URL 上带 `?b=<指纹>`；
   指纹由 `standalone/boot.js` 挂到 globalThis.__worldolBuild 提供。这是 MainActivity 之外的第二道保险。
3. `世界online_原版单机/web/index.html` 里那个按钮的「宠物商店（143种）」是**写死的数量**，
   宠物目录一变就过期、很容易被当成「新宠物没上架」 → 改成打开面板时由 recorded-content.js
   按 /api/supply-shops 的下发值回填。注意 index.html 必须保持 CRLF。

顺带排除一种可能：VFS 的 readOnlyText 是**内存** Map，只有存档走 localStorage，
不存在「旧资料被持久化」这第二层。

## ② 宠物幻化后场景里那只不变
不是界面没重画，是场景里的宠物实体没拿到新数据：SceneController.addObj 里只在「玩家模型进场景」
那一次把 p.vo = t.pet 绑死；服务端每次下发 playerDetail 都会造新 VO 并 setPet（不带通知），
于是 myPlayer.pet 早就换过对象了、实体还攥着旧的 → 界面跟着新对象走、场景贴图跟着旧对象走。

修法（web/pet-illusion.js 新增 resyncScenePet）：照抄原生「宠物出战」那条路，
setPet(active, true) → ON_PET_ADD → 实体重绑 + onAdded() 重算贴图；只对**正在出战的这只**做。

**判定必须按槽位**：第一版写成「引用相同或 petItem 相同」，看着对，实际会被上面那条坑掉 ——
服务端重建过 VO 之后两个引用必然不同，必漏判。现在「引用相同 / petItem 相同 / 槽位相同」
任一条命中即算同一只，并补了一条专门钉它的用例（引用不同、槽位相同 → 仍要刷新场景）。

## 蓝条看不到的真因（前三版方向就错了）
- 游戏**自带** `_hpBar`/`_mpBar`：单位精灵 `updateHpBar/updateMpBar`，
  挂到 `battleSprite.parent`，`y=this.y+height+5` / `2*height+5`（蓝条本就画在血条下面），
  缩略图 `fight_panel_mp2`。截图里那条「白框红条」就是它。
- 每帧 `BattlePanel.paint → hideAllPlayerMsg → hideMsg()` 把三条全关；只有出手时 `drawCurMsg`
  开血条，**蓝条只在 `go.isRePlayBattle`（战斗录像）才开** → 正常打怪永远没有蓝条。
- 修：改 `hideMsg()` —— 怪物（`isMonster && !isDead`）保留 HP+MP，其它原样。自绘那套整段删除。

## 「0 蓝还回蓝」
- 会。模块 251 `doRoundHpMp`：`MANA_RECOVERY`(61) + 天生状态 `BUFFER_ADD_MP`（+0.5% 上限），
  法力 0 也照样回。
