## 第 43 版 · 修「装备幻化后重新登录卡黑屏」

玩家：某个角色做过装备幻化后，重新登录选它进入就卡黑屏，其他角色正常。

**根因 = 第 4 次「两份实现」**：装备幻化的合法性有两处判定，规则还不一样 ——
- `lib/illusion-service.mjs` 用「**同槽位**即可」（我们有意放开的：所有武器共用槽 [8,10]）；
- `lib/restoration-packets.mjs` 的 `itemPacket` 用「**同 type**」（`appearance.type!==e.type`）。

于是「能存、不能读」：剑幻化成刀（都占 [8,10]）→ 幻化服务放行、写进存档；
重新登录下发时 itemPacket 抛错。而 **itemPacket 在「进入世界的整包」里**
（`enterWorld`→`worldData`(默认 detail=true)→`playerDetail`→`combatRating`→`nativeCharacterStats`
→`itemPacket`，以及 `bagPacket`），一抛错整包发不出去 → 客户端一个字节都收不到 → **黑屏**。
在 combatRating 阶段就会先炸一次，所以连地图数据都发不出。

- 复现（不开手机）：装备 28003(type=13) 幻化成 20457(type=14)，同槽位 [8,10]
  → 抛「幻化外观与装备类型不匹配。」；改成同类型 → 正常。
- 玩家存档里 5 个角色共 12 条幻化**全是同 type**（所以以前没炸）。

**修法**：
1. 新增 `lib/illusion-policy.mjs` 作唯一判定（`shareEquipSlot` / `illusionBlockReason` /
   `noteIllusionFallback`），幻化服务与下发物品包都 import 它；
2. `itemPacket` **不合法就降级按本体下发、绝不抛错**（代价只是外观不显示，
   而抛错是「玩家永远进不去、只能删号」）；降级记录在 `illusionFallbacks()`；
3. 幻化写入时新增「外观必须有 definitionBase64」校验，提前挡住会写坏的数据。

**恢复**：玩家**不需要删角色**，修复后那件装备照常显示幻化外观。

- 测试：`tests/illusion.test.mjs` 8 条（+6）。含一条**源码级「只准有一份实现」断言**
  （两个文件都必须 import illusion-policy，不许再出现 `appearance.type!==` 与本地 shareSlot 定义）。
- 负向实验：回退成「同 type」+ 降级改回抛错 → 4 条红、报错正是那句旧文案；恢复后 8/8。
- npm test 71 文件 / 467 用例 / 全过。
- 玩家说「先别引入自定义的宠物框架，还是像以前那样打包就行」→ 框架保持原样不动
  （默认零只自制宠物、惰性、对行为零影响），打包流程无变化。

## 工具篇：底模参考包导出器（不改游戏，无新包）

玩家问「pet-reskin-templates 里都是什么、怎么照着画」。翻出这是**一次性脚本**的产物，
且里面有两处会把人带偏的错，于是把它做成正式工具 `tools/export-pet-reskin-templates.mjs`。

**两个真实错误（都已修）**
1. **只认 `assets/<hash 前两位>/`**：资源还有一部分在 `assets/dirad/`（53 个文件）。
   于是 frag12013（哈士奇主体 163×89 / 玛玛哈哈头像）被判成「没有图集」，布局整块丢失。
   → 解析必须 `assets/<前两位>/` 失败后**回退 `assets/dirad/`**。
2. **「用到的部件」按整个 model 并起来算**：`frames` 的值是 `[贴图下标, 部件号, x, y, flag]`，
   必须按**第一项（贴图下标）**过滤再统计。并起来算的结果：frag12065（图集 8 个部件）
   标成「用到 17 个」、frag15042（3 个部件）标成「用到 45 个」。
   已加用例钉住「textureUsage 按 slot 分开」。

**术语订正（重要）**：model json 里 `frames` 的**键是姿态/朝向**（504→4 个、516→9 个、
548→6 个、532→22 个、708→9 个），值是「若干**部件**的拼装清单」；
`anis[].gesture = [[姿态号, 停留帧数, 0, 0], ...]` 才是动画时间线（`id 0` 待机、`id 2` 攻击）。
以前写成「每朝向 7~8 帧」是把部件数说成了帧数。

**「要不要画」的判据 = 被多少个 model 引用**（`GENERIC_REFERENCE_LIMIT=500` 判通用件）。
实测真正要画的张数：玛玛哈哈 2 / 哈士奇 4 / 熔岩 3 / 仙灵 3 / **幼年蓝龙 5**
（蓝龙槽位 1~9 的 frag11008/1001/2001/3001/6001/7001/4001/1/10021 全是
1000~2150 个 model 共用的通用件）—— 之前跟玩家说的「蓝龙 10 张」是错的。

**踩坑**：默认输出路径用 `new URL('../../../../MobileFile/…', import.meta.url)` 拼，
少了一层 → 真的往 `源码/MobileFile/` 写了一批（已移入临时目录回收，无原有文件受影响）。
现在工具会检查**输出目录的父目录是否存在**，不存在直接退出。相对路径层级别凭感觉数。

**其他**：文件名改 `slot<槽位>_frag<编号>_<宽>x<高>.png`（槽位 = `files` 下标 =
reskin 配置 `replace` 填的数）；旧 `NN_frag…` 命名每次导出清掉；SVG 布局图用红框标「用到的部件」。
`npm test` 74 文件 / 484 用例 / 全过；新增 `tests/pet-reskin-export.test.mjs`（4 条）。
语法基线第一时间抓住了「模板字符串里嵌反引号」的笔误。

## 工具篇②：宠物精灵号用错了字段 → 底模参考包整体挑错底模

玩家问「重绘人形宠物用哪只底模」，一查发现参考包**全部挑错**：它把
`data/pet-catalog.json` 的 `baseline.model` 当精灵号，**那是模板号**
（480/504 条与 `templateId` 完全相同，只有 model=-1 与 鬼神/恶鬼 例外）。
拿它查 sprite/model 表得到的是毫不相干的精灵（把 model 的 frames 真拼成图看过：
504→火焰元素、516→天空战神/苍鹰、548→气球怪、708→骑马的骑士）。

**真正的入口是抓包来的 `baseline.icon`**（客户端 `SpriteTool.getPetSpriteByIcon`）：

```
style = icon 低 6 位（LEN_PET_STYLE，1..63）
世界/地图精灵 = SPR_INDEX_PET_WORLD_START(500) + style - 1
战斗精灵     = SPR_INDEX_PET_BATTLE_START(600) + style - 1
颜色        = icon 第 6~7 位（LEN_PET_COLOR，2 位）→ 引擎按它调色
```
→ **一个风格号 = 一整套贴图**，多只宠物共用只差配色（红炎少女色3/魔法少女色0/虚无少女色2
同一套；黑夜猫女色2/可爱猫女色0/红艳猫女色1 同一套）。
→ **世界与战斗是两套不同的 model**：实测 52 个风格里 0 个相同，换皮必须两套都换。
→ `headIcon` 与世界精灵号有 437/504 相同、67 条差 1~2，是**另一套号**，别当成一回事。

**人形成本（专属件张数）**：style2 女仆 1 张(112×61，世界战斗通用) / style12 猫女 1 张 /
style20 少女 1 张(145×72) / style28 鬼神·style30 女娲·style31 蛇妖·style34 九尾狐 各 2 张 /
style21 骑士 3 张 / style16 女仆 4 张 / style26 灯神 4 张 / style44 人马 5 张。
**空风格号 = 22,23,24,25,38,39,40,45,46,49~63**（自制宠物用它们才不会连带改到原有宠物）。

改动：新增 `lib/pet-sprite.mjs`（编号唯一来源，两个工具共用）；导出工具改成**按风格号**
（`世界/`+`战斗/`+`头像/`，`--styles`/`--list`/`--clean`）；换皮构建新增 `battle` 部位
（`baseBattle`）与 `modelIds`（客户端按风格号算号，必须指定），漏 baseBattle 打 ⚠；
`local-pet-art/README.md` 的四步流程与示例全部改对。
`npm test` 74 文件 / 488 用例 / 全过；`check` 291 文件 0 错误。**不动游戏逻辑，无需重打 APK。**

踩的坑：语法基线抓不到「引用了已删除的局部变量」（`drawable is not defined`），
它只做 parse —— 这类错只能靠跑工具本身发现。
