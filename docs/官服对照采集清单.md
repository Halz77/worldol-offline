# 官服网页版对照采集清单

> 目标：把官服网页版当作**权威参照系**，补齐、校准本地单机版的数据和公式。  
> 官服只用于抓包和对照，不作为本地运行的依赖。
>
> ⚠ 原始抓包可能包含账号、Cookie、角色信息、聊天和其他玩家信息。  
> **原始包只留在本机，不要提交到仓库，不要公开上传。**

---

## 一、采集前准备

### 1. 确认工具

在 `世界online_原版单机/` 下确认：

```text
tools/capture-official-web.mjs     本次新增的网页抓包器
tools/analyze-capture.mjs          抓包分析
tools/analyze-recordings.mjs       批量分析（可选）
../正式服录制工具/lib/             录制协议解析库
node_modules/ws/                   WebSocket 依赖
```

需要 Node.js 22 左右。

### 2. 使用独立浏览器配置

不要用日常 Chrome 配置，避免扩展、登录状态和缓存干扰。  
使用单独的 `--user-data-dir`，抓完可以整个删掉。

### 3. 准备测试账号

- 用专门的测试账号，不要用主账号。
- 不要抓其他玩家、聊天、邮件等隐私内容。
- 充值免费版本只做手动验证，不要自动化刷充值。

### 4. 留足磁盘空间

官服网页资源可能有几百 MB，一次完整会话的原始包可能到 1–3 GB。  
建议至少留 5 GB，原始包放在仓库外或已被 `.gitignore` 忽略的目录。

### 5. 一场采集的范围

- **版本侦察**单独一场，只做登录、角色面板、背包、技能、宠物。
- **副本数据**可以连续走，不用每个副本都停一次；自动标记会按地图和战斗切分。
- 建议一场控制在 30–40 分钟，或原始包 1–2 GB 以内；超过就输入 `q` 收尾，再开下一场。
- 每场都要真正打完战斗，不要只点入口/退出；战斗结算和奖励才是要补的数据。

## 二、启动抓包

### 1. 启动 Chrome

PowerShell：

```powershell
& "$env:ProgramFiles\Google\Chrome\Application\chrome.exe" `
  --remote-debugging-port=9222 `
  --remote-allow-origins=* `
  "--user-data-dir=$env:TEMP\worldol-capture-profile" `
  about:blank
```

Edge：

```powershell
& "${env:ProgramFiles(x86)}\Microsoft\Edge\Application\msedge.exe" `
  --remote-debugging-port=9222 `
  --remote-allow-origins=* `
  "--user-data-dir=$env:TEMP\worldol-capture-profile" `
  about:blank
```

注意：

- 第一次采集保留 `about:blank` 作为初始页面，抓包器会先接管它，再导航到官服网页。
- **同一只浏览器可以反复抓**：停止抓包后不要关浏览器，下次直接运行抓包器，
  用 `--match` 选中已经开着的游戏页即可，角色可以继续走，不需要重新登录。
- 只有浏览器被关掉时，才需要用上面的命令重新启动；`--user-data-dir` 会保留登录状态。
- `--remote-allow-origins=*` 只对本机调试端口开放，抓完关掉浏览器即可。
- 不要把远程调试端口暴露到公网。

### 2. 启动抓包器

在 `世界online_原版单机/` 下：

```powershell
node tools/capture-official-web.mjs `
  --port 9222 `
  --url "官服网页地址" `
  --label "20261022-01-login"
```

参数说明：

| 参数 | 说明 |
| --- | --- |
| `--port` | Chrome 远程调试端口，默认 9222 |
| `--url` | 官服网页地址；第一次采集从 about:blank 接管并导航，后续继续抓可省略 |
| `--label` | 本次会话标签，写进 `session.json` |
| `--match` | 按 URL 关键字选择已有页面；第二次起建议用它选中游戏页 |
| `--out` | 输出根目录，默认 `../正式服录制数据` |
| `--no-auto-marks` | 关闭自动标记（默认开启） |
| `--seconds` | 自动结束秒数，仅用于测试，不建议正式采集使用 |

第二次继续抓同一个角色时，不需要重新打开浏览器，也不需要再传 `--url`：

```powershell
node tools/capture-official-web.mjs `
  --port 9222 `
  --match "world-h5" `
  --label "20261023-02-dungeons"
```

启动成功后会打印：

```text
抓包目录：...\正式服录制数据\2026-10-22T...
采集开始。正常玩官服网页版；地图/战斗/任务会自动标记，终端可输入 `m 说明` 补标记，输入 `q` 回车结束。
```

### 3. 自动标记（默认开启）

抓包器会读取 WebSocket 帧头，在关键动作自动写标记，不需要手动输入：

```text
自动：进入地图 37（风雪之城）
自动：战斗开始 group=1234
自动：战斗结束 group=1234
自动：接任务 mission=1001 npc=50
自动：交任务 mission=1001 npc=50
```

自动标记只读协议号和公开字段，不改变原始帧。  
如果某次不想自动标记，加 `--no-auto-marks`。

### 4. 手动补标记（可选）

自动标记之外，仍可在终端输入：

```text
m 登录完成
m 角色面板
m 背包
m 宠物列表
m 商店-武器
m 副本-葬送三队长
```

标记会写进抓包，分析时能快速定位。  
输入 `q` 回车结束；也可以按 `Ctrl+C`，抓包器会尽量正常收尾。

结束后应看到：

```text
抓包已保存：...\正式服录制数据\...
```

## 三、第一场：版本侦察（必做）

这场不追求数据量，只确认官服客户端和协议版本。

### 要做的事

1. 打开官服网页，等资源加载完。
2. 登录，进入角色选择，进入游戏。
3. 打开角色面板、背包、技能、宠物各看一次。
4. 正常退出，输入 `q` 结束。

### 要检查的文件

结束后运行：

```powershell
node tools/analyze-capture.mjs "../正式服录制数据/<抓包目录名>"
```

重点看：

```text
analysis/summary.json
analysis/resources.json
analysis/protocols.json
analysis/decode-checks.json
```

`resources.json` 里找：

```text
/v/gd/305.json
/v/gd/其他版本号.json
/js/...
```

如果仍是 `305`，再和本地对比：

```powershell
Get-FileHash "client\v\gd\305.json" -Algorithm SHA256
```

### 判定

- **官服仍是 v305**：价值最大，可以复用现有解析器和大半数据流程。
- **官服已经是新版本**：不要直接覆盖 `data/official-v305.json`；先单独建 `data/references/official-YYYYMMDD/`，做协议差异报告。
- 如果 `decode-checks.json` 有大量 `Scene block ... not yet decoded`，说明新协议或新场景块，先记录，不要强行导入。

## 四、采集清单

### P0：优先采，直接影响本地数据质量

| 会话 | 做什么 | 目标数据 |
| --- | --- | --- |
| P0-1 版本与资源 | 首次加载、登录、进入游戏 | 客户端版本、资源清单、协议表、初始场景包 |
| P0-2 角色与背包 | 打开角色面板、属性、技能、装备、称号、VIP | 角色面板字段、装备定义、技能等级、称号/套装 |
| P0-3 宠物 | 宠物列表、每只宠物详情、技能、成长、进化 | 宠物模板、宠物属性、宠物技能、成长/进化规则 |
| P0-4 商店与道具 | 每个商店分类看一遍，买 1 件便宜道具，使用/装备 | 商店 ID、价格、库存、道具完整定义 |
| P0-5 任务 | 主线 1–2 张地图，接取 → 推进 → 提交 | 任务条件、对话、奖励、接取/交付 NPC |
| P0-6 战斗 | 普通怪 + BOSS 各打一场，尽量打满 20–50 回合 | 怪物属性、编队、AI、伤害/命中/暴击/格挡样本 |

#### P0-2 角色与背包

- 打开角色面板，切到每个页签。
- 打开背包，逐类点开装备详情，尤其是：
  - 武器：剑、刀、枪、锤、拳套、法杖等
  - 防具：头、衣、裤、鞋、披风
  - 首饰：戒指、项链、护符
- 打开技能列表，记录职业、技能等级、22 级效果。
- 打开称号、套装、VIP 面板。
- 标记：`m 角色面板`、`m 背包-武器`、`m 技能列表`。

#### P0-3 宠物

- 宠物列表每只点开一次。
- 记录：等级、品质、成长、领悟、血蓝、五维、技能、天生技能。
- 有条件的话，做一次升级/进化前后对比。
- 标记：`m 宠物列表`、`m 宠物详情-<名字>`。

#### P0-4 商店与道具

- 每个商店分类都点开，不要只看第一页。
- 买 1 件最便宜的道具，触发购买回包。
- 对目标装备做一次：装备、卸下、查看详情。
- 如果方便，做一次鉴定/强化/镶嵌/附魔/赋灵，记录消耗和结果。
- 标记：`m 商店-<分类>`、`m 购买-<道具>`、`m 鉴定-<装备>`。

#### P0-5 任务

- 每个类型至少一条：
  - 主线
  - 日常
  - 城市任务
  - 副本入口任务
- 完整走一遍：接取 → 对话 → 打怪/收集 → 提交 → 领奖。
- 标记：`m 接任务 <id>`、`m 任务进度 <id>`、`m 提交任务 <id>`。

#### P0-6 战斗

- 普通怪、精英、BOSS 各一场。
- 战斗前记录：角色面板、宠物、buff、装备。
- 战斗中尽量多打几回合，不要一击秒杀。
- 战斗后记录：经验、铜币、掉落、任务进度。
- 同一只怪最好重复 20–50 次，用于公式统计。
- 标记：`m 战斗开始 group=<id>`、`m 战斗结束`。

## 五、分析抓包

### 1. 单场分析

```powershell
node tools/analyze-capture.mjs "../正式服录制数据/<抓包目录名>"
```

会生成：

```text
analysis/summary.json
analysis/items.json
analysis/skills.json
analysis/missions.json
analysis/monsters.json
analysis/groups.json
analysis/ai.json
analysis/catalog.json
analysis/scene-packets.json
analysis/decode-checks.json
analysis/protocols.json
analysis/resources.json
```

先看：

- `summary.json`：完整性、协议类型、解码通过率
- `decode-checks.json`：哪些包没解出来
- `protocols.json`：官服用到哪些协议
- `resources.json`：客户端版本和资源哈希

### 2. 批量分析

如果 `正式服录制数据/` 下有多场：

```powershell
node tools/analyze-recordings.mjs
```

注意：这个脚本会检查客户端是否仍是 v305。  
如果官服已经升级，它会跳过，不会污染现有数据。

### 3. 不要急着导入

`import-official-capture.mjs` 会写 `data/official-v305.json`，并要求客户端文件哈希一致。  
只有同时满足下面条件才导入：

1. 官服客户端仍是 v305
2. 目标协议解码完整
3. 每条数据都有 `sources`（seq / 协议号 / SHA256）
4. 先做 diff，确认没有把旧数据覆盖坏
5. `npm test` 通过

如果官服是新版本，先写对比报告，不要直接导入。

## 六、数据落库规则

| 内容 | 放哪里 | 是否入库 |
| --- | --- | --- |
| 原始抓包 | `正式服录制数据/` | 否，已忽略 |
| 单场分析 | 抓包目录下 `analysis/` | 否 |
| 对照报告 | `docs/对比报告-官服-YYYYMMDD.md` | 可以 |
| 验证过的数据 | `data/references/official-YYYYMMDD/` | 可以 |
| 现有 v305 数据 | `data/official-v305.json` | 只有确认同版本才更新 |

原则：

- 原始包不进 Git。
- 分析结果只保留必要字段和 source 引用。
- 不把官服账号、Cookie、聊天、其他玩家信息写进任何导出文件。
- 不把官服客户端资源重新打包进公开仓库。

## 八、安全与合规

- 只抓自己的账号和自己的操作。
- 不抓聊天、邮件、其他玩家列表；如果不小心抓到，分析前过滤，原始包不公开。
- 不自动化刷副本、刷充值、攻击服务器。
- 不把官服当运行时依赖；本地单机仍然离线运行。
- 官服客户端、素材、商标归原权利人所有；本项目只做个人研究。
- 公开仓库继续不包含 `client/`、`analysis/`、原始抓包和账号信息。
