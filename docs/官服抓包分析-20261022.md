## 二、客户端版本结论

### 1. 资源清单仍是 v305

官服资源清单：

```text
/cnb/bd-cdn/world-res@main/v/gd/305.json
```

SHA-256：

```text
ff9d4224d4f57e3ae616cdcafcd07bd7dae5977e6adff67b6d0b93f9409ab005
```

本地：

```text
世界online_原版单机/client/v/gd/305.json
```

哈希完全一致，大小都是 407,511 字节。  
所以**官服当前仍然是 v305 资源清单**，这一点对导入最有利。

### 2. 主包不是逐字节一致

对比抓到的 JS：

| 资源 | 官服 | 本地 | 结果 |
| --- | ---: | ---: | --- |
| `js/ff/fff570...js` | 4,697,799 B | 4,696,705 B | **不同**，官服多 1,094 字节 |
| `gd.js` | 14,777 B | 18,581 B | **不同**，本地是另一份引导脚本 |
| `api.js` | 14,066 B | 不存在 | 官服新增的 4399 SDK |
| 其余 9 个 `js/*` | 与本地一致 | 与本地一致 | 哈希全部相同 |

`fff570` 的第一处差异是反外挂判断和自动模式处理：

- 本地：`if (t.indexOf(go.subchannel) <= -1) ...`
- 官服：`if (t.indexOf(go.subchannel) > -1) ...`
- 本地：`var i = "true" == e.function_switch;`
- 官服：`var i = !a.default.isAccelerate; if ("flag" in e) i = e.flag;`

这说明官服主包是一个**比本地略新的 v305 构建**，不是数据版本更新。  
结论：

- **数据定义可以用 v305 的口径对照**
- **不要直接把现有 `import-official-capture.mjs` 跑上去**：它会因为 `fff570` 哈希不同、以及新的 CDN 路径前缀 `/cnb/bd-cdn/world-res@main/` 而报错
- 暂时不要把官服主包覆盖到本地 `client/`；本地主包带着单机补丁链的锚点

## 九、本轮结论

### 可以直接用的

1. **确认官服仍是 v305 资源清单**。
2. 46 件已有道具的基础字段与官服一致，说明本地道具定义总体可靠。
3. 找到 17 件真正缺失的道具定义，可作为下一版补充。
4. 找到 5 个缺失的装备技能等级。
5. 找到 2 个推算错误的技能等级（708/715）。
6. 找到 1 个真正缺失的任务（3805）和 1 个任务类型差异（728）。
7. 找到个人城市 3000 的 13 个 NPC 坐标，可作为城市专题的起点。

### 不能直接用的

1. **不要直接跑 `import-official-capture.mjs`**：CDN 前缀和 `fff570` 哈希都会让它失败。
2. 不要把抓包里的装备实例字段当成定义字段。
3. 不要用本轮任务列表推断接取/奖励。
4. 不要用本轮数据改战斗、怪物、掉落或副本。
5. 不要覆盖本地 `client/fff570...js`：官服主包和本地补丁链锚点不是同一份。
