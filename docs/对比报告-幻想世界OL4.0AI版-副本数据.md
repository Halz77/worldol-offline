### 5.2 他们怎么补的

`data/dungeon-reward-repairs.json`（169 条，字段 `id/name/bagIcon/grade/kind/taskMaterial/referenceItemId/days`）
+ `lib/dungeon-reward-repairs.mjs`（`decoded` 11527—11613）：

1. **自动登记**：遍历所有任务奖励/条件，凡是没定义的道具自动进 `rows`（用奖励元组里的 name/bagIcon/grade）。
2. **克隆定义**：拿参考道具（默认 **1351**，169 条里 154 条用它；其余用 2002/2003/2011/2017…/15128）
   clone 一份，改 `id/name/bagIcon/grade`，`type` 统一成 **28**（可开箱/消耗品），
   `power1 = 100`（`101` 表示「锁」），`powerValue1 = 0`；`definitionBase64` 由
   `dungeonRewardDefinition()` 现场拼（`equipment` / `fashion` 类走 `equipmentBytes()`）。
3. **分类**：`reward 63 / materialToken 43 / token 25 / equipment 12 / food 5 / construction 5 /
   question 4 / blessing 4 / fashion 3 / gear 3 / material 1 / petEquip 1`。
4. **服饰类**带 `days` 过期（`p.dungeonRewardExpiresAt`，`normalizeDungeonRewardItems` 清理）。
5. **材料掉落**：`dungeonRewardMaterialDrops()` 按任务 `submitCondition` 的
   `CONDITION_HAVE_ITEM` + 怪物名/地图过滤，在战斗胜利时补发（花灯、青蛙、鬼竹、孤魂、小偷、矿精…）。

   任务 3030「国家专用发展证领取」把「消耗 500 国家贡献度」换成「拥有个人城市」条件
   （我们的 AGENTS 里也记着这条「待定」）。

## 附：解包与复现

```bash
# 1) 解包 assets/www（跳过 client/assets）
python - <<'EOF'
import zipfile,os,glob
apk=glob.glob('/mnt/c/Users/hal/Desktop/*4.0AI*.apk')[0]
dst='/mnt/c/Users/hal/AppData/Local/Temp/opencode/fxol4'
z=zipfile.ZipFile(apk)
for i in z.infolist():
    n=i.filename
    if not n.startswith('assets/www/'):continue
    rel=n[len('assets/www/'):]
    if not rel or rel.startswith('client/assets/'):continue
    out=os.path.join(dst,rel); d=os.path.dirname(out)
    if d and not os.path.isdir(d):os.makedirs(d)
    open(out,'wb').write(z.read(i))
EOF

# 2) 解密服务端 bundle（Base64 → 逐字节 XOR 0x5A）
node -e "const fs=require('fs');const b=Buffer.from(fs.readFileSync('fxol4/client/worldol-standalone.js','utf8').trim(),'base64');for(let i=0;i<b.length;i++)b[i]^=0x5a;fs.writeFileSync('fxol4lib/worldol-standalone-decoded.js',b.toString('utf8'))"
```

解包脚本与本报告用到的探针都留在 `%TEMP%\opencode\`（`fx4-*.mjs` / `fx4-*.sh`），
4.0 的 APK 仍在桌面；本目录只记结论，不存对方数据副本。
