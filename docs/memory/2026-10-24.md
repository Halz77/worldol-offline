APK 的 `worldol-formation-panel.js` 并没有被它的启动脚本加载，服务端也缺世界数据下发；
本地 v305 客户端主包本来就有完整的阵法协议、列表和属性面板。因此这次**不搬 web 面板**，
直接接原生界面：

- `lib/formation-data.mjs`：16 个阵型、16 本玖级书（`62009—62144`，间隔 9），
  编号/数值与 APK 5.0 的 `FORMATION_DATA_9` / `FORMATION_BOOKS_9` 一致；说明文字补了两个缺失的 `%`（APK 的天地三才阵把智力/体质写成无百分号）。
- `lib/official-data.mjs`：`applyFormationBooks()` 在**装备覆盖之前、建索引之前**注入，
  这样 `officialItems`、`restoration.equipment`、商店和装备编辑器都能看到。
- `lib/supply-shops.mjs`：新增分类 `922 阵法书`，16 本全部免费。
- `lib/restoration-service.mjs`：接 `14012` 学书、`14013` 遗忘、`14015` 切换/清空默认。
- `lib/world.mjs`：登录世界数据置 `DATA_FORMATION (1<<20)`，下发完整块。
- `lib/restoration.mjs`：阵型 power 并入 `powers(p,'equipment')`，因此 `attributes()` 会算。
- `lib/native-character-stats.mjs`：给 `nativePlayer` 挂 `formationSkill` 桩，面板/战力/
  战斗校验走客户端同一套 `getBaseValue/getPowerValue`。
- `lib/client-formation-book-patch.mjs`：只改一条字符串，让 `type31` 的「使用」分支排除
  `power1=182`，阵法书才会走 `14012` 而不是人物技能书 `14007`。主包 4,568,725 → 4,568,770。

### 三个必须记住的坑

1. **世界数据不能只发列表**。客户端 `processDataWorld` 的顺序是
   `doGetFormation(t)` → `getBoolean()` → 有当前阵时 `fromByteFormationSkill(t)`。
   只发 count+列表会让客户端把下一段数据当 bool 读，登录后 `formationSkill` 为空。
   现在 `formationWorldBlock()` 负责「列表 + bool + 当前 skill」。
2. **14012 首字节是 formationtype，不是 0**。客户端
   `doUseFormationBookItemCb` 用首字节 `l` 去替换 `formationList` 里的同号项
   （`l==p.formationtyep`），写 0 会让重复使用的书在列表里追加重复项。
3. **formationSkill 的 `skillId` 必须写阵型 id，不能写 0**。客户端「设为默认 / 遗忘」
   会把列表项的 `i.skillId` 原样发给 `14015/14013`；APK 5.0 写 0，等于每次点都请求
   清空/遗忘 0。本地写 `f.id`，切换和遗忘才按用户点的那一项工作。

### 14014 同步

客户端的 `14012/14013/14015` 回调**只刷新 `formationList`，不刷新 `myPlayer.formationSkill`**；
属性面板和战斗都读后者。所以 `server.mjs` 的 `finally` 每次调 `syncFormation()`，
状态一变就补推 `14014`。不要恢复「第一次只记基线」的优化：登录后第一件事如果是学书/切阵，
就会漏推。重复推同一状态会被 `lastFormationId` 跳过。

## 2. 副本链复审（只报告，不移植）

- 本地 `daily-dungeon-directory.mjs` 38 行；APK 5.0 39 行，唯一新增是 `97 血魔遗迹`（排除）。
- APK 行里的 `unavailable` 大多已过时：本地已补齐 63/64/70/73/76/79/80/87/88/90/94/95/96。
  仍真实缺：77 缺地图 943、78 缺任务 941、86 缺地图 973。
- APK `repaired-dungeons.json` 的 14 张动态副本地图在本地全部存在，逐张核对地图/NPC/
  编队/怪物无缺失；`replayable-chains.json` 本地 8 条，APK 只有 1 条，本地是超集。

  任务材料，导致 15 条目录行的任务链交不了。APK 的完整方案带 `90031/90032` 欠账/回执，
  不建议整包搬；要修就只补这 26 个 `type=28` 任务材料。详见
  `docs/对比报告-幻想世界OL5.0副本排行榜修复版.md` 第 11.3 节。
