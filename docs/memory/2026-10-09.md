## 本轮任务：武器幻化解除类型限制（第 15 版 APK）

用户要求：武器幻化不再限制「同类型」，武器之间可任意互幻（大刀 → 法杖）。

### 根因：三处「同类型」判定
1. 服务端 `lib/illusion-service.mjs` `candidatesFor()`：只下发 `item.type===source.type`；
2. 服务端同文件幻化校验：`appearance.type!==definition.type` 直接拒绝；
3. 客户端主包两处：
   - BagChange 视图 `onShow()`：`n.type==e.type` 过滤候选；
   - `Item.isIllusion()`：`o.type==this.type` 决定「幻化」按钮是否显示。

- 新增 `lib/client-illusion-patch.mjs`（`illusion-any-weapon-v1`）：客户端两处判定改为

- 服务端顺手去掉 `slice(0,127)`。

### 连带坑（都要一起改，缺一个就整包失败）

## 第 18 版 —— 武器幻化后贴图不跟手（v17 守卫其实没生效）

### 根因链（重要，以后改角色贴图都按这个来查）
- 角色贴图 = **躯体模型**（`assets/sprite/model/{nameID}.json`，含手臂姿势 + 每个零件的
  绘制偏移）+ **零件碎片**；两层都只认 `icon2`。
- `nameID` = `SpriteTool.getSpriteIdByIcon(icon1, icon2, icon3)` →
  `getSpriteNameIDByWeapon(基础体, 左武器style, 右武器style, 双持, 战斗)`：
  左右 style 先 `(style-1)>>4` 换成「武器类型组」再映射成模型号
  （113 单手剑 / 136 双手锤 / 163 双剑 / 144 单手锤 …）。
  **最后一句 `var l=r;0!=s&&(l=s)` —— 右手会盖掉左手，姿势以右手为准。**
- 武器碎片 = `getWeaponIcon(左 style, color)`；右手只是双持模型里的第二个零件槽。
- ⇒ 两把武器类型组不同时：姿势按右手、贴图按左手 → 贴图不跟手（飘在身后），
  右手武器也照样画出来（「大锤有时候还在」）。
- 关键数据：`START_WEAPON=8000`、`START_WEAPON_ADD1=30000`；数据里武器 icon 全是
  8001~9113（无 ADD1）；每类型 16 个 style；`(style-1)>>4` 组号 → 类型码经 remap
  （组 25→34球、26→35枪、27→36双枪、28→37单锤、29→38双锤、30→39扇；组 24 盾→0）。
- `getWeaponIcon(style,color) = style>500 ? 30000+((style-500)<<2)-3+color
  : 8000+(style<<2)-3+color`（往返一致）。

### ★ 教训：往压缩代码里插守卫必须挂在「最终条件」上
v17 把守卫写成了 `if( A, B, GUARD&&C&&(e=t), 最终条件 )` 里的一句中间语句 ——
逗号表达式的中间值直接丢弃，**if 只看最后一个表达式**，守卫等于没生效。
以后凡是给 `if(逗号表达式)` 打补丁，都要把守卫并进最后那个表达式。

### 本版改动
- `lib/client-weapon-icon-patch.mjs` → `weapon-icon-v2`：
  · 左右两槽都做幻化解算；
  · 右手槽显示守卫挂在最终条件上：左槽无可显示武器（空槽/盾 icon=0）→ 放行；
    左右「解算幻化后的类型组」相同且都不是双手类型 → 放行（双剑/剑盾原样）；
    其余 → 只画左手。类型组：13~23、34~39 用自身，24 及其它 = 0。
- 新增 `tests/weapon-icon-patch.test.mjs`：补丁幂等 + v1 写法不得复现 + **抽出改后真实
  条件表达式用 mock 现场求值**（9 个组合）。这套「抽条件表达式来跑」的验证法值得复用。
- 已知未动：`getEquipWeaponType()`（读背包原始类型，不认幻化）只影响战斗动作层
  （`getAttakAnimePos` / `getAttackRangeAnime` / ATK_TIME 加成），贴图不吃这条路径。

## 第 19 版 —— 宠物幻化（新功能，候选限传说级）

**① 按钮点不动 = 监听被 `doHide` 摘掉，而视图是复用的。**
- `Mdr.doHide` 收尾会把 `__egretHandler` 里登记的监听**全部摘掉**：
  `for(o=this.__egretHandler;o.length;){o.pop().target.removeEventListener(...)}`。
- `Owner.showView` 复用实例：`var r=a.__mdrIns[e]; r||(r=a.__mdrIns[e]=new a.__mdrCls[e](i), …)`，
  只有闲置超过 `Mdr_Dispose_T` 才 `dispose()`。⇒ `_view` 与按钮对象一直在。
- 旧代码用 `source.onEgret(button, TOUCH_TAP, …)` 注册 → 关一次界面监听就没了；
  而 `installButton` 见 `view.__petIllusionBtn` 已存在就 early return，永远不再重挂
  → 按钮画在屏幕上但彻底哑掉。「刷新角色列表」不重载页面，所以照旧点不动。
- 修法：`button.addEventListener(TOUCH_TAP, view.__petIllusionTap, view)` 直接挂在按钮上
  （不进 `__egretHandler`，`doHide` 摘不到），监听只挂一次。

**② 看不到变化 = 刷新走的是带缓存的路径。**
- `mdr.onBagEquipemntUpdate()` → `_proxy.doPetSeeMsg`，而 `doPetSeeMsg` 有两道跳过：

  宠物界面早就加载过详情 → 永远不重新请求 → 一直画旧外观。

- 注意应答格式：服务端 `petDetail(new Writer().byte(0), pet)` = **[状态字节][id=0][name…]**，
  所以读完状态字节后整段交给 `fromBytesDetail` 正好对齐 `doPetSeeMsg` 的写法。

**③ 附带**：`submit` 里 `finally{render();}` 会把刚写的提示文案重置成「候选 N 种…」，

## 第 23 版：修「宝石替换」点确定没反应（第 22 版引入的回归）

### 根因（重要项目机制，务必记住）
**`sendProtoAsync` 会替某些协议先吃掉应答的第一个字节当状态位。**
客户端 `analysis/modules/0035.js`：

```js
e.resultMsg = new Set([...])   // 167 个协议
sendProtoAsync(t,i,r){ ... var o=t.body;
  e.resultMsg.has(r) ? (n = Handler.processMessage(o,i)) : Handler.setMsgTag(r,o);
  resolve(n ? o : null);
}
Handler.processMessage = (t,i)=>{ var o=t.getByte();
  0>o ? (alertMessageGuide(t.getString(),i), false) : (setMsgTag(t.getType(),t), true); }
```
⇒ 只要请求类型在 `resultMsg` 里，**服务端应答必须先用 `byte(0)` 写一个状态字节**：
负数＝失败并自带文案（框架直接弹给玩家、本次请求作废），>=0＝成功，剩下的字节才给调用方。
不在 `resultMsg` 里的协议，状态字节由调用方自己读。

已核实：
| 协议 | 在 resultMsg？ | 服务端应答 |
|---|---|---|
| 11507 CG_REPLACE_INLAY_GEM | 在 | 必须 `byte(0)+byte(条数)+各槽位` |
| 11508 CG_REPLACE_INLAY_GEM_ASK | 不在 | `byte(0)+装备数据`，状态由客户端自己读 |
| 12019 CG_BAG_REPAIR | 在 | `byte(0)+int(铜币)`（本项目早就这么写了） |
| 11505 CG_COMPOSITE_CONFIRM / 12018 CG_STORAGE_OPER | 在 | 同理需要状态字节 |
| 14009/14010 主动技能设置 | 在，但客户端用 `sendProto`+手动 `onProto` | 不受影响 |

第 22 版的 11507 回包写成 `byte(条数)+各槽位`（少状态字节）⇒ 客户端把我的条数(1)当状态、
把「槽位高字节(31~40 恒为 0)」当条数 → 消耗清单空 → 确认时发 0 条 → 服务端拒绝 →
**界面上就是「点确定没有任何反应」**。

## 追加：正式服录制工具的使用链路（用户将自行录制美容院数据）

### 结论：**包里只有解析库，没有工具本体**
- `世界OL_源码/正式服录制工具/` 只有 `lib/`（11 个 cjs/js）+ `package.json` + `依赖说明.txt`；
  `package.json` 的 `main: "main.cjs"` 但 **main.cjs 不存在**；`依赖说明.txt` 原话：
  「只附带单机源码所需的公共录制协议解析库；不含录制界面、Electron 或登录缓存」。

  `import-official-guides.mjs` / `reconcile-catalog.mjs` 都依赖它。

### 工具原理（从 lib 读出来的，可信）
- Electron 应用，用 `webContents.debugger`（CDP：`Network.enable` +
  `Target.setAutoAttach`）把 **HTTP 响应体 + 全部 WebSocket 帧**落盘。
- 往游戏页面注入两个桥：
  · `catalog-bridge.js` —— 用页面已登录连接主动问一批目录/详情协议
    （白名单：32101→32102、16051、12060、14001、16005、11501、11053、11055、
    11160、12052、11026、15514、16009）＝界面上的「补齐装备与技能 / 攻略树 / 传送门」；
  · `portal-bridge.js` —— NPC（npcType 3/5/8）传送门目标列表。
- **白名单里没有 12004/12005** ⇒ 美容院商品必须**手动点开商店**才录得到。

### 归档格式（archive.cjs）
`正式服录制数据/<ISO时间戳_id>/`：

隐私：原始归档含账号/角色/聊天，**不可外发**。
